## 1. The Mental Model

A production Python service is a set of boundaries: external data is validated at the edge, I/O is coordinated by an event loop, and shared resources are owned by the application lifespan. Most intermittent failures come from confusing boundaries, such as blocking the event loop, re-opening clients on every request, or logging an error without enough context to follow it.

Use a repository for data access, a service for business rules, and a route for HTTP translation. A route can then report a problem without exposing internal errors, while testing the service with a small fake rather than a live database.

| Concern | Where it belongs |
| --- | --- |
| Environment and secrets | Validated settings at process start |
| Connections and pools | Lifespan-managed resources |
| Validation and HTTP errors | Route boundary and exception handlers |
| Business rules | Service functions and typed contracts |
| Data access | Repositories, with transaction behavior explicit |
| Diagnostics | Structured logs, request IDs, traces, and metrics |

## 2. Core Architecture & How It Works Under the Hood

```text
 client
   |
   | HTTP request, request ID
   v
 ASGI server ---> event loop ---> FastAPI middleware and router
                     ^                    |
                     | resume at I/O      | validate / inject dependencies
                     |                    v
                     +--------------- service ----> repository / HTTP pool
                                           |
                                           +----> JSON logs + OTel spans
```

1. Uvicorn parses requests into ASGI messages. Each coroutine runs until it yields on an awaitable. Blocking I/O or CPU work on the loop delays other requests.
2. Validation creates typed inputs before business logic runs. Dependency injection passes collaborators without making the route own their lifecycle.
3. Lifespan starts once per worker process. Open clients and instrumentation there and close them during shutdown. Each worker has a separate memory space, which matters for in-memory state.
4. REST is request/response. Server-Sent Events (SSE) keeps a response open for server-to-client text events. WebSocket upgrades to a bidirectional message channel. Apply timeouts, cancellation, and backpressure to streaming work.
5. A request ID ties logs together across functions. OpenTelemetry spans describe parent/child work and duration. Metrics summarize rates and latency. Avoid high-cardinality request IDs and personal identifiers in metric labels.

### Paths, settings, and typed contracts

```python
from dataclasses import dataclass
from pathlib import Path
from typing import Annotated, Protocol, TypeVar

from pydantic import BaseModel, Field
from pydantic_settings import BaseSettings, SettingsConfigDict

T = TypeVar("T")


class Settings(BaseSettings):
    model_config = SettingsConfigDict(env_file=".env", env_prefix="APP_", extra="ignore")
    payload_dir: Path = Path("payloads")


class Reading(BaseModel):
    sensor: Annotated[str, Field(min_length=1)]
    count: Annotated[int, Field(strict=True, ge=0)]


@dataclass(frozen=True, slots=True)
class ReadingKey:
    sensor: str


class ReadingStore(Protocol):
    async def get(self, key: ReadingKey) -> Reading | None: ...


def first(items: list[T]) -> T | None:
    return items[0] if items else None


settings = Settings()
print(Reading.model_validate({"sensor": "north", "count": 3}).model_dump())
```

`Path` composes paths without string concatenation. `env_file` loads local overrides and `env_prefix` makes the variable for the directory `APP_PAYLOAD_DIR`. `extra="ignore"` permits unrelated entries in a shared dotenv file. `Annotated` carries field constraints alongside a static type. `strict=True` rejects strings in the integer field, and `ge=0` requires nonnegative values. A frozen dataclass is useful as a value key. `slots=True` removes the per-instance attribute dictionary. Structural `Protocol` lets collaborators satisfy a contract without inheritance. `TypeVar` preserves the item type through `first`. Expected output contains sensor north and count 3.

### Daily collections and resource management

```python
from collections import Counter, defaultdict, deque
from contextlib import ExitStack
from datetime import UTC, datetime
from functools import lru_cache, partial, wraps
from itertools import batched
from pathlib import Path
from tempfile import TemporaryDirectory
from zoneinfo import ZoneInfo
import shutil
import subprocess
import sys


@lru_cache(maxsize=64)
def normalize_key(value: str) -> str:
    return value.casefold().strip()


def tagged(function):
    @wraps(function)
    def wrapper(*args, **kwargs):
        return function(*args, **kwargs)
    return wrapper


counts = Counter(normalize_key(name) for name in [" North ", "north", "south"])
grouped = defaultdict(list)
grouped["north"].append(3)
recent = deque([1, 2, 3], maxlen=3)
chunks = list(batched([1, 2, 3, 4, 5], 2))
run_python = partial(subprocess.run, check=True, capture_output=True, text=True, timeout=2)

with ExitStack() as stack:
    root = Path(stack.enter_context(TemporaryDirectory()))
    source = root / "sample.txt"
    source.write_text("ready", encoding="utf-8")
    shutil.copy2(source, root / "backup.txt")
    process = run_python([sys.executable, "-c", "print('ready')"])
    print(process.stdout.strip(), counts["north"], chunks[-1])

recorded_at = datetime.now(UTC)
display_time = recorded_at.astimezone(ZoneInfo("Asia/Kolkata"))
```

- `lru_cache(maxsize=64)` caches hashable argument sets for a pure function with bounded storage. `partial` pre-binds common arguments. `wraps` preserves wrapped metadata that frameworks inspect.
- `Counter` counts occurrences, `defaultdict(list)` creates a list on a missing key, and a bounded `deque` evicts the opposite end when full. `batched` groups iterables lazily, with a shorter final tuple in Python 3.12.
- `ExitStack` owns a dynamic set of cleanup callbacks. `TemporaryDirectory` provides an isolated workspace, and `shutil.copy2` copies file data and supported metadata.
- `subprocess.run` takes an argument list without shell interpretation. `check` raises on a nonzero exit, `capture_output` collects streams, `text` decodes them, and `timeout` bounds the wait. Expected output: `ready 2 (5,)`.
- Store aware UTC instants. Convert to named `ZoneInfo` zones for display. Keep the timezone database installed on portable deployments.

### Async I/O and bounded retries

```python
from contextlib import asynccontextmanager

import httpx
from tenacity import (
    retry, retry_if_exception_type, stop_after_attempt, wait_random_exponential,
)


@asynccontextmanager
async def upstream():
    async with httpx.AsyncClient(
        timeout=httpx.Timeout(3.0, connect=0.5),
        limits=httpx.Limits(max_connections=20),
    ) as client:
        yield client


@retry(
    retry=retry_if_exception_type((httpx.ConnectError, httpx.ConnectTimeout)),
    wait=wait_random_exponential(multiplier=0.1, max=1.0),
    stop=stop_after_attempt(3),
    reraise=True,
)
async def fetch_health(client: httpx.AsyncClient, url: str) -> dict:
    response = await client.get(url)
    response.raise_for_status()
    return response.json()
```

`asynccontextmanager` runs setup before yielding and cleanup after exit. A single `AsyncClient` reuses connections. The timeout sets default per-operation bounds with a shorter connect timeout, and the limit caps concurrent connections. Use an overall request deadline where required. Tenacity retries only the listed transient connect errors, spreads attempts with jittered exponential delay, makes at most three attempts, and reraises the last error. The returned value is decoded JSON. Validate upstream payloads before treating them as trusted data. Retry a write only when its semantics and idempotency guarantees allow it.

**`app.py`**

```python
import asyncio
from collections.abc import AsyncIterator
from contextlib import asynccontextmanager
from http import HTTPStatus
from typing import Annotated, Protocol, cast
from uuid import uuid4

import structlog
from fastapi import Depends, FastAPI, HTTPException, Request, Response, WebSocket
from fastapi.responses import JSONResponse, StreamingResponse
from opentelemetry.instrumentation.fastapi import FastAPIInstrumentor
from pydantic import BaseModel
from pydantic_settings import BaseSettings, SettingsConfigDict
from structlog.contextvars import bind_contextvars, clear_contextvars


class Settings(BaseSettings):
    model_config = SettingsConfigDict(env_prefix="STATION_")
    instrument: bool = False


class Count(BaseModel):
    station: str
    riders: int


class Repository(Protocol):
    async def get(self, station: str) -> Count | None: ...


class FixtureRepository:
    async def get(self, station: str) -> Count | None:
        return Count(station=station, riders=12) if station == "central" else None


class Counts:
    def __init__(self, repo: Repository) -> None:
        self.repo = repo

    async def require(self, station: str) -> Count:
        count = await self.repo.get(station)
        if count is None:
            raise HTTPException(404, "Station not found")
        return count


def get_counts(request: Request) -> Counts:
    return cast(Counts, request.app.state.counts)


def create_app(settings: Settings | None = None) -> FastAPI:
    settings = settings if settings is not None else Settings()

    structlog.configure(processors=[
        structlog.contextvars.merge_contextvars,
        structlog.processors.add_log_level,
        structlog.processors.TimeStamper(fmt="iso", utc=True),
        structlog.processors.JSONRenderer(),
    ])
    log = structlog.get_logger()

    @asynccontextmanager
    async def lifespan(application: FastAPI) -> AsyncIterator[None]:
        # A production repository would open and close its pool here.
        application.state.counts = Counts(FixtureRepository())
        yield

    application = FastAPI(lifespan=lifespan)

    @application.middleware("http")
    async def request_context(request: Request, call_next) -> Response:
        request_id = uuid4().hex
        clear_contextvars()
        bind_contextvars(request_id=request_id)
        try:
            response = await call_next(request)
            response.headers["X-Request-ID"] = request_id
            log.info("request_completed", status=response.status_code)
            return response
        finally:
            clear_contextvars()

    @application.exception_handler(HTTPException)
    async def problem(request: Request, error: HTTPException) -> JSONResponse:
        return JSONResponse(
            status_code=error.status_code,
            media_type="application/problem+json",
            headers=error.headers,
            content={
                "type": "about:blank", "title": HTTPStatus(error.status_code).phrase,
                "status": error.status_code, "detail": error.detail,
                "instance": request.url.path,
            },
        )

    @application.get("/stations/{station}")
    async def station_count(station: str, counts: Annotated[Counts, Depends(get_counts)]) -> Count:
        return await counts.require(station)

    @application.get("/events")
    async def events(counts: Annotated[Counts, Depends(get_counts)]) -> StreamingResponse:
        async def snapshots() -> AsyncIterator[str]:
            for _ in range(2):
                count = await counts.require("central")
                yield f"event: count\ndata: {count.model_dump_json()}\n\n"
                await asyncio.sleep(0.2)
        return StreamingResponse(snapshots(), media_type="text/event-stream")

    @application.websocket("/live")
    async def live(socket: WebSocket) -> None:
        await socket.accept()
        service = cast(Counts, socket.app.state.counts)
        await socket.send_json((await service.require("central")).model_dump())
        await socket.close()

    if settings.instrument:
        FastAPIInstrumentor.instrument_app(application)
    return application
```

## 5. Common Pitfalls & Debugging Playbook

### 1. One slow endpoint delays unrelated requests

**Symptom:** Latency climbs for simple endpoints while a handler runs blocking work.

**Root Cause:** The handler monopolizes the event-loop thread.

**Diagnostic:** Compare overlapping requests to the slow and fast routes and inspect event-loop lag alongside spans.

**Fix:** Use an async client for I/O. Move blocking operations to an appropriate worker and CPU-bound jobs to a process or queue.

### 2. Outbound connections accumulate

**Symptom:** Connection setup dominates request time and file descriptor pressure rises.

**Root Cause:** New pools are created per request or a stream is never closed.

**Diagnostic:** Compare client construction counts to request counts and inspect socket states.

**Fix:** Own shared clients in lifespan, close streamed bodies reliably, and bound the pool and operation timeouts.

### 3. Settings depend on the launch directory

**Symptom:** A service starts from a shell but deployment reads different values.

**Root Cause:** A relative dotenv location is resolved from the current working directory.

**Diagnostic:** Check the process working directory and the presence of required variable names without printing secret values.

**Fix:** Make runtime configuration explicit and validate it during startup.

### 4. Error logs cannot be joined to a trace

**Symptom:** A 500 appears in a proxy log with no correlated application event.

**Root Cause:** Context was not bound at the request boundary, or an event was logged outside the propagated task context.

**Diagnostic:** Send a single request and compare response headers, JSON log fields, and trace attributes.

**Fix:** Bind and clear request context consistently, propagate trace context across service calls, and never place request IDs in metric labels.

### 5. A retry creates duplicate writes

**Symptom:** A timed-out request triggers two side effects.

**Root Cause:** The first write completed, but its response was lost and the operation was replayed.

**Diagnostic:** Compare business keys and trace spans for both attempts.

**Fix:** Enforce idempotency and a bounded retry budget, or require reconciliation before retrying an ambiguous write.

## 7. Mastery Checkpoint Questions

### Q1. An async route calls a synchronous HTTP client directly. Why do other requests stall?
- A. The middleware resets the pool for every request.
- B. The call occupies the event-loop thread without yielding.
- C. HTTP responses can only be read by worker processes.
- D. A context variable blocks the event loop by design.

<details>
<summary>Answer & Explanation</summary>

**Answer: B.** Async concurrency requires cooperative suspension. Use an async I/O client or isolate blocking work from the loop.

</details>

### Q2. Where should a shared HTTP client be opened and closed for each application worker?
- A. Inside every route.
- B. In a per-request exception handler.
- C. In the application lifespan.
- D. Inside a cached property without a cleanup path.

<details>
<summary>Answer & Explanation</summary>

**Answer: C.** Lifespan gives resources explicit ownership and allows requests to reuse the pool across the worker's lifetime.

</details>

### Q3. Why should a request ID not be used as a Prometheus metric label?
- A. Unique IDs create an unbounded number of time series.
- B. Request IDs must always be integers.
- C. Prometheus has no labels.
- D. Labels prevent histogram creation.

<details>
<summary>Answer & Explanation</summary>

**Answer: A.** Each distinct label combination creates a series. Use a route template for metrics and put correlation IDs in logs or spans.

</details>

### Q4. A write times out after being sent upstream. What makes a retry safe?
- A. Always increasing the timeout.
- B. Retrying only over a new connection.
- C. Adding a larger delay.
- D. An idempotency guarantee or reliable confirmation that the first write did not commit.

<details>
<summary>Answer & Explanation</summary>

**Answer: D.** A lost response does not prove a failed write. Use a stable operation key or reconcile the outcome before replaying it.

</details>

### Q5. What should a timezone-sensitive service persist for an event that already occurred?
- A. An unzoned local wall-clock string.
- B. A timezone-aware UTC instant.
- C. The current UTC offset alone.
- D. A locale-specific display date without a time.

<details>
<summary>Answer & Explanation</summary>

**Answer: B.** Persist an unambiguous instant and apply a named timezone at display time so daylight-saving transitions are handled by appropriate rules.

</details>

### Q6. Design the lifecycle of a shared async upstream client in a FastAPI service. How would you verify that startup, request reuse, and shutdown all work while testing with different settings?

<details>
<summary>Answer & Explanation</summary>

Create one bounded client per worker in the lifespan context and expose it through a dependency. Close it when that context exits. In tests, scope settings overrides with monkeypatch and enter the TestClient context. Inject or instrument a fake transport to confirm multiple requests reuse the client and that it is closed during teardown.

</details>
