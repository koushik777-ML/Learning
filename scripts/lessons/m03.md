## 1. The Mental Model

A production Python service is a set of boundaries: external data is validated at the edge, I/O is coordinated by an event loop, and shared resources are owned by the application lifespan. Most intermittent failures come from confusing boundaries, such as blocking the event loop, re-opening clients on every request, or logging an error without enough context to follow it.

Use a repository for data access, a service for business rules, and a route for HTTP translation. A route can then report a problem without exposing internal errors, while testing the service with a small fake rather than a live database.

| Concern | Where it belongs |
| --- | --- |
| Environment and secrets | Validated settings at process start |
| Connections and pools | Lifespan-managed resources |
| Validation and HTTP errors | Route boundary and exception handlers |
| Business rules | Service functions and typed contracts |
| Data access | Repositories, with transaction behavior explicit |
| Diagnostics | Structured logs, request IDs, traces, and metrics |

### Define ownership and contracts before writing routes

A service behaves like a staffed intake desk. The route accepts requests in the language callers use, the service makes the domain decision, and the repository keeps an accurate record. The building owns shared utilities such as upstream connection pools. If every visitor opens a new utility connection, it becomes harder to manage capacity and close resources.

For each operation, sketch what is valid input, which decisions require durable state, which collaborators can fail, and which outputs can be replayed. Define time and concurrency budgets from the user's request inwards. Keep a small set of public error categories with documented meanings. Internals may evolve without changing how clients decide whether to correct, retry, or abandon a request.

| Layer | Example decision | Test in isolation |
| --- | --- | --- |
| Settings | Is the upstream deadline positive and within the request budget? | Override the environment and construct the settings object. |
| Input model | Is the submitted rider count a nonnegative integer? | Validate valid, malformed, and ambiguous values. |
| Domain service | Does this station permit a new reading? | Substitute a repository containing known sample records. |
| Repository | Is there a current record, and is the update committed atomically? | Use a real storage integration for constraints and transaction behavior. |
| Route | Which status and response fields represent the outcome? | Exercise the real route through a test client. |
| Runtime | Can overloaded callers recover without starving healthy requests? | Use timing, cancellation, and saturation scenarios. |

## 2. Core Architecture & How It Works Under the Hood

```text
 client
   |
   | HTTP request, request ID
   v
 ASGI server ---> event loop ---> FastAPI middleware and router
                     ^                    |
                     | resume at I/O      | validate / inject dependencies
                     |                    v
                     +--------------- service ----> repository / HTTP pool
                                           |
                                           +----> JSON logs + OTel spans
```

1. Uvicorn parses requests into ASGI messages. Each coroutine runs until it yields on an awaitable. Blocking I/O or CPU work on the loop delays other requests.
2. Validation creates typed inputs before business logic runs. Dependency injection passes collaborators without making the route own their lifecycle.
3. Lifespan starts once per worker process. Open clients and instrumentation there and close them during shutdown. Each worker has a separate memory space, which matters for in-memory state.
4. REST is request/response. Server-Sent Events (SSE) keeps a response open for server-to-client text events. WebSocket upgrades to a bidirectional message channel. Apply timeouts, cancellation, and backpressure to streaming work.
5. A request ID ties logs together across functions. OpenTelemetry spans describe parent/child work and duration. Metrics summarize rates and latency. Avoid high-cardinality request IDs and personal identifiers in metric labels.

### From socket to response

The server and application meet at ASGI. The scope carries connection facts such as route, headers, and protocol. The application consumes events through `receive` and produces events through `send`. For HTTP the response starts with status and headers, followed by one or more body messages. By the time the client receives headers for a stream, the server cannot turn a later generator error into a different HTTP status. Validate inputs and important upstream preconditions before opening a stream. Communicate a recoverable in-stream condition through documented event semantics or end the stream cleanly.

Request dependencies can authenticate a caller, provide typed parameters, and obtain application resources. The app owns long-lived resources such as a shared HTTP client. Dependencies often own a short-lived transaction or request context and clean it up at the appropriate scope. Avoid keeping an open transaction while sending an unbounded stream to a slow client. Design a separate read or replay path if clients need to consume slowly.

Each worker process imports code separately, creates its own event loop and pools, and can fail separately. Four workers with a maximum of 20 outbound pool connections each can attempt up to 80 such connections per instance. Multiply by replicas and include capacity used by jobs and administration. State shared across workers belongs in a coordinated system, such as a database, when it participates in correctness. Use per-worker memory for replaceable caches, with conservative bounds and explicit lifetime.

### What scheduling and cancellation actually mean

Calling an async function creates a coroutine object. Awaiting it drives the coroutine, while scheduling it as a task lets other tasks make progress between suspension points. Awaiting an immediately completed operation need not yield control to the loop. A CPU-heavy parse or a synchronous network request in an async handler blocks the loop until control returns. This can delay deadlines, websocket heartbeats, and unrelated requests. Thread offload is useful for blocking I/O libraries. Isolate heavy CPU work in a process or queue when appropriate. A timeout around an awaiting task does not guarantee a blocking thread or an upstream operation stopped.

Structured concurrency keeps child tasks within a defined owner. When a task in an `asyncio.TaskGroup` fails with an unexpected exception, sibling tasks are cancelled and the group reports the failures after cleanup. Treat cancellation as a control signal. Release resources with context managers and `finally` blocks, and let the cancellation proceed. Do not hide it inside a catch-all error result. If the operation must continue after the client disconnects, give it a durable owner and explicit status rather than tying it to a request task.

### Pick a transport from who needs to speak

| Interface | Use when | Plan for |
| --- | --- | --- |
| REST request/response | One action or read has a bounded result | Deadlines, status codes, validation, and retry semantics |
| Server-sent events | Events flow primarily from server to client and text framing is useful | Blank-line framing, reconnect, optional cursors, buffering, and slow readers |
| WebSocket | Client and server both send messages over a live session | Authentication, message schemas, close handling, idle timeouts, and bounded queues |

Server-sent events use UTF-8 text with fields such as `event:`, `id:`, and `data:`. A blank line dispatches the event. If reconnects must resume without loss, preserve monotonic event IDs and a replay window and define what to do when a cursor is too old. Proxy buffering can delay delivery even when the app yields promptly. For WebSockets, handle disconnects as routine and use a bounded output queue if producers can outpace the client. Choose whether to drop replaceable snapshots, reject producers, or disconnect clients. Never allow queue growth to define your memory limit.

## 3. Complete Command, Query & Python Syntax Reference (Progressive)

### Paths, settings, and typed contracts

```python
from dataclasses import dataclass
from pathlib import Path
from typing import Annotated, Protocol, TypeVar

from pydantic import BaseModel, Field
from pydantic_settings import BaseSettings, SettingsConfigDict

T = TypeVar("T")


class Settings(BaseSettings):
    model_config = SettingsConfigDict(env_file=".env", env_prefix="APP_", extra="ignore")
    payload_dir: Path = Path("payloads")


class Reading(BaseModel):
    sensor: Annotated[str, Field(min_length=1)]
    count: Annotated[int, Field(strict=True, ge=0)]


@dataclass(frozen=True, slots=True)
class ReadingKey:
    sensor: str


class ReadingStore(Protocol):
    async def get(self, key: ReadingKey) -> Reading | None: ...


def first(items: list[T]) -> T | None:
    return items[0] if items else None


settings = Settings()
print(Reading.model_validate({"sensor": "north", "count": 3}).model_dump())
```

`Path` composes paths without string concatenation. `env_file` loads local overrides and `env_prefix` makes the variable for the directory `APP_PAYLOAD_DIR`. `extra="ignore"` permits unrelated entries in a shared dotenv file. `Annotated` carries field constraints alongside a static type. `strict=True` rejects strings in the integer field, and `ge=0` requires nonnegative values. A frozen dataclass is useful as a value key. `slots=True` removes the per-instance attribute dictionary. Structural `Protocol` lets collaborators satisfy a contract without inheritance. `TypeVar` preserves the item type through `first`. Expected output contains sensor north and count 3.

### Decide which type system addresses which boundary

An annotation lets a type checker reason about source code. It does not automatically validate an incoming HTTP body. Pydantic models bring validation to runtime and can serialize to structured outputs. `Reading.model_validate(...)` checks a Python object and produces a model or a validation error. `Reading.model_validate_json(...)` accepts JSON input. `model_dump()` returns Python data, while `model_dump(mode="json")` produces JSON-compatible values and `model_dump_json()` returns encoded text. For example, a Python datetime can remain a datetime in the default dump and become an ISO-formatted string in JSON mode. Keep secrets and internal fields out of public output by building an explicit output model.

With Pydantic v2, optional and omittable are separate. `comment: str | None` accepts a string or null but still requires the field. `comment: str | None = None` supplies a default when absent. This matters for patch operations, where a missing field may mean “keep current value” and explicit null may mean “clear it.” `model_dump(exclude_unset=True)` omits fields that were not provided. Be equally deliberate about coercion. Taking a strict integer at an API boundary can reveal client errors early, while settings sourced from environment strings must support the intended parsing.

A `dataclass` provides generated initialization, equality, and field conventions for internal Python objects. It does not enforce input types at runtime. Frozen is shallow: a frozen dataclass can still contain a mutable list. Use tuples or another immutable representation if keys rely on stable hashing. A `Protocol` describes the behavior a dependency must offer; tests can supply a different class whose methods match that contract. Do not introduce a repository interface solely to duplicate an ORM's method list. Shape the operations around the domain need and transaction boundary.

### Resolve configuration once at startup

In the typical settings source order, constructor values take precedence over environment variables, which take precedence over dotenv values, then secret files and defaults. Projects can customize that order. A relative `env_file` is interpreted against the working directory, and a service launch can have a different directory than a developer's shell. Choose an explicit development configuration location or let deployments supply variables directly. Keep the set of required values small, validate once per application instance, and report missing keys by name without echoing values. Never make a request's isolated settings change mutate global configuration for others.

`pathlib` makes locality explicit: relative paths are interpreted by the process at I/O time, and an absolute right-hand path overrides the left of a join. `resolve()` normalizes components and follows symlinks. If a caller submits a path, do not treat a string prefix match as a containment check. Prefer identifiers that your application maps to paths. For controlled fixtures, compare the resolved candidate to the resolved root using path components, and understand that hostile concurrent filesystem changes require stronger operating system controls. An atomic replacement on the same filesystem can publish a fully written file so readers observe an old or new snapshot. That alone does not guarantee crash durability.

### Daily collections and resource management

```python
from collections import Counter, defaultdict, deque
from contextlib import ExitStack
from datetime import UTC, datetime
from functools import lru_cache, partial, wraps
from itertools import batched
from pathlib import Path
from tempfile import TemporaryDirectory
from zoneinfo import ZoneInfo
import shutil
import subprocess
import sys


@lru_cache(maxsize=64)
def normalize_key(value: str) -> str:
    return value.casefold().strip()


def tagged(function):
    @wraps(function)
    def wrapper(*args, **kwargs):
        return function(*args, **kwargs)
    return wrapper


counts = Counter(normalize_key(name) for name in [" North ", "north", "south"])
grouped = defaultdict(list)
grouped["north"].append(3)
recent = deque([1, 2, 3], maxlen=3)
chunks = list(batched([1, 2, 3, 4, 5], 2))
run_python = partial(subprocess.run, check=True, capture_output=True, text=True, timeout=2)

with ExitStack() as stack:
    root = Path(stack.enter_context(TemporaryDirectory()))
    source = root / "sample.txt"
    source.write_text("ready", encoding="utf-8")
    shutil.copy2(source, root / "backup.txt")
    process = run_python([sys.executable, "-c", "print('ready')"])
    print(process.stdout.strip(), counts["north"], chunks[-1])

recorded_at = datetime.now(UTC)
display_time = recorded_at.astimezone(ZoneInfo("Asia/Kolkata"))
```

- `lru_cache(maxsize=64)` caches hashable argument sets for a pure function with bounded storage. `partial` pre-binds common arguments. `wraps` preserves wrapped metadata that frameworks inspect.
- `Counter` counts occurrences, `defaultdict(list)` creates a list on a missing key, and a bounded `deque` evicts the opposite end when full. `batched` groups iterables lazily, with a shorter final tuple in Python 3.12.
- `ExitStack` owns a dynamic set of cleanup callbacks. `TemporaryDirectory` provides an isolated workspace, and `shutil.copy2` copies file data and supported metadata.
- `subprocess.run` takes an argument list without shell interpretation. `check` raises on a nonzero exit, `capture_output` collects streams, `text` decodes them, and `timeout` bounds the wait. Expected output: `ready 2 (5,)`.
- Store aware UTC instants. Convert to named `ZoneInfo` zones for display. Keep the timezone database installed on portable deployments.

### Use lazy iteration and bounded memory intentionally

Using an iterator leaves the source to be consumed on demand. Helpers such as `itertools.chain.from_iterable` flatten one level and `islice` bounds an iterator without materializing the full input. Iterators are generally single-use. If the source must be reused, create a fresh iterator or store only the bounded slice you need. `groupby` starts a new group each time the key changes in the input order. Sort compatible data before grouping, or use a dictionary accumulator when order is arbitrary and the key set can be bounded. `batched` yields tuples up to the chosen size. Use batches for incremental import and define how a partial last batch or failed batch should be handled.

`defaultdict` only creates a missing entry on ordinary indexing; use `get` for a lookup that should not change the map. A bounded `deque` is useful for the last N observations, a sliding window, or a bounded recent-history cache. It does not provide a complete event history. `Counter` is convenient for inspecting a batch, but a counter keyed by unbounded user values can consume unbounded memory. For monitoring, aggregate over a controlled vocabulary.

Use `lru_cache` for repeated pure computations with inexpensive keys or to memoize stable results with a defined lifetime. Its cache is per process and holds references to keys and values. It will not coordinate replicated workers or invalidate data after a write. Do not directly apply it to an `async def`: it caches the coroutine object instead of the completed value. `partial` packages a function call with preset arguments, while `wraps` preserves details such as the name, docstring, and wrapped-function metadata. If you wrap a coroutine, keep an asynchronous wrapper so it can await the original call.

For file work, create temporary directories inside their owning context and use `ExitStack` for dynamically acquired resources. Its teardown runs last-in first-out when a later acquisition fails. `shutil.copy2` attempts to preserve metadata, but ownership and all system-specific properties need separate treatment. For subprocess work, pass a trusted executable path and a list of arguments, set a timeout, and interpret its documented return code. Separate small captured output from long-running streams or large files. Avoid retaining sensitive stdout and stderr. Bound both the work performed and the amount of output you keep.

### Treat time as two different data types

Persist event instants as timezone-aware UTC. A date interpreted as 09:00 in a named zone is different from an existing instant formatted for a reader. Store the zone name and business rule when a future schedule is supposed to follow a local wall clock, since the offset can change by date. Daylight-saving transitions can skip a local time or make it ambiguous. The `fold` flag distinguishes the two occurrences during a fall-back where supported, but a business input still needs an explicit ambiguity policy. Use a monotonic clock for elapsed durations and timeout deadlines so changes to system wall time do not create negative measurements.

### Async I/O and bounded retries

```python
from contextlib import asynccontextmanager

import httpx
from tenacity import (
    retry, retry_if_exception_type, stop_after_attempt, wait_random_exponential,
)


@asynccontextmanager
async def upstream():
    async with httpx.AsyncClient(
        timeout=httpx.Timeout(3.0, connect=0.5),
        limits=httpx.Limits(max_connections=20),
    ) as client:
        yield client


@retry(
    retry=retry_if_exception_type((httpx.ConnectError, httpx.ConnectTimeout)),
    wait=wait_random_exponential(multiplier=0.1, max=1.0),
    stop=stop_after_attempt(3),
    reraise=True,
)
async def fetch_health(client: httpx.AsyncClient, url: str) -> dict:
    response = await client.get(url)
    response.raise_for_status()
    return response.json()
```

`asynccontextmanager` runs setup before yielding and cleanup after exit. A single `AsyncClient` reuses connections. The timeout sets default per-operation bounds with a shorter connect timeout, and the limit caps concurrent connections. Use an overall request deadline where required. Tenacity retries only the listed transient connect errors, spreads attempts with jittered exponential delay, makes at most three attempts, and reraises the last error. The returned value is decoded JSON. Validate upstream payloads before treating them as trusted data. Retry a write only when its semantics and idempotency guarantees allow it.

### Bound concurrency and elapsed time separately

```python
import asyncio


async def run_batch() -> list[int]:
    limit = asyncio.Semaphore(2)

    async def fetch(index: int) -> int:
        async with limit:
            await asyncio.sleep(0.01)  # Simulate a cancellable network wait.
            return index * index

    async with asyncio.timeout(1):
        async with asyncio.TaskGroup() as group:
            tasks = [group.create_task(fetch(index)) for index in range(5)]
    return [task.result() for task in tasks]


print(asyncio.run(run_batch()))
```

`Semaphore(2)` permits up to two tasks inside the limited region. `TaskGroup.create_task` starts an owned task and gives it the group's lifetime. `asyncio.timeout(1)` bounds the entire block to one second, including time spent waiting for permits. `task.result()` is safe after the group finishes successfully. Expected output is `[0, 1, 4, 9, 16]` in submission order even if tasks finish in a different order. For a large or unbounded work source, use a bounded queue and fixed workers instead of starting an unbounded number of tasks waiting on the semaphore.

An HTTPX client has connect, read, write, and pool-acquisition timeouts. The read timeout usually bounds waiting for the next chunk of data, so a trickle of chunks can keep a read alive beyond a desired total request budget. Wrap eligible work in a whole-operation deadline. A pool timeout may indicate excessive local concurrency, so immediately retrying it can worsen saturation. Fit the retry stops and waits inside the deadline, use a policy that distinguishes transient from permanent errors, and verify that each request attempted an acceptable operation. Idempotent reads are easier to retry safely than writes whose outcome is unknown after disconnect.

### Give logs, metrics, traces, and errors independent jobs

A structured log is a discrete event with fields such as `event`, `request_id`, `route`, `status`, and `duration_ms`. Correlation IDs help find related log entries. Distributed tracing propagates trace context across services and records nested timed spans. A trace ID can link a log event to a trace when your logging integration records it. Metrics aggregate outcomes; use route templates such as `/stations/{station}` in labels and keep raw station IDs or request IDs out so the number of series remains bounded. Record request count, errors, and durations, then supplement with pool waits, active connections, and loop delay when they help explain bottlenecks.

Instrument a request from the ASGI boundary, create child spans around I/O or significant actions, and keep span attributes free of credentials and private payloads. Propagating a header requires an approved trust and privacy policy. Generate server-controlled correlation IDs or normalize any client-provided values before logging. Stream completion and transport cancellation may occur after response headers are sent, so measure handler execution and stream lifetime separately when diagnosing long-lived connections.

Problem Details uses the media type `application/problem+json`. `type` identifies a stable class of problem and defaults to `about:blank`, which relies on HTTP status semantics. `title` is a human-readable summary, `status` matches the HTTP status, `detail` describes this instance, and `instance` can identify the occurrence when appropriate. Clients should make decisions from the HTTP status and stable type or typed extension fields. Keep stack traces, internal hostnames, and raw exception values in protected diagnostics. Use `422` or the documented input status for a malformed domain payload, `404` for a missing resource, `409` for state conflicts, and `503` when required service capacity is unavailable.

### Make tooling and tests reproducible

Keep declared dependencies in `pyproject.toml` and commit the resolved lockfile for applications. Match the deployment Python range and select an interpreter in CI. Linting catches rule violations, formatting establishes consistency, type checking checks annotated contracts across runtime paths, and runtime tests verify the behavior itself. These checks are complementary. Use narrow test doubles at boundaries you own, with a few real integrations that catch an incorrect approximation of external behavior.

Use pytest fixtures to create per-test state and yield resources that need to be closed. If settings come from environment values, build the settings object after `monkeypatch.setenv`. `monkeypatch.delenv` can exercise missing settings. Match the full ASGI lifespan in integration tests by opening the TestClient as a context manager. If using another asynchronous test transport, verify that it runs lifespan or manage startup and shutdown explicitly. Test failures with bounded waits and controllable fakes instead of slow arbitrary sleeps.

**`app.py`**

```python
import asyncio
from collections.abc import AsyncIterator
from contextlib import asynccontextmanager
from http import HTTPStatus
from typing import Annotated, Protocol, cast
from uuid import uuid4

import structlog
from fastapi import Depends, FastAPI, HTTPException, Request, Response, WebSocket
from fastapi.responses import JSONResponse, StreamingResponse
from opentelemetry.instrumentation.fastapi import FastAPIInstrumentor
from pydantic import BaseModel
from pydantic_settings import BaseSettings, SettingsConfigDict
from structlog.contextvars import bind_contextvars, clear_contextvars


class Settings(BaseSettings):
    model_config = SettingsConfigDict(env_prefix="STATION_")
    instrument: bool = False


class Count(BaseModel):
    station: str
    riders: int


class Repository(Protocol):
    async def get(self, station: str) -> Count | None: ...


class FixtureRepository:
    async def get(self, station: str) -> Count | None:
        return Count(station=station, riders=12) if station == "central" else None


class Counts:
    def __init__(self, repo: Repository) -> None:
        self.repo = repo

    async def require(self, station: str) -> Count:
        count = await self.repo.get(station)
        if count is None:
            raise HTTPException(404, "Station not found")
        return count


def get_counts(request: Request) -> Counts:
    return cast(Counts, request.app.state.counts)


def create_app(settings: Settings | None = None) -> FastAPI:
    settings = settings if settings is not None else Settings()

    structlog.configure(processors=[
        structlog.contextvars.merge_contextvars,
        structlog.processors.add_log_level,
        structlog.processors.TimeStamper(fmt="iso", utc=True),
        structlog.processors.JSONRenderer(),
    ])
    log = structlog.get_logger()

    @asynccontextmanager
    async def lifespan(application: FastAPI) -> AsyncIterator[None]:
        # A production repository would open and close its pool here.
        application.state.counts = Counts(FixtureRepository())
        yield

    application = FastAPI(lifespan=lifespan)

    @application.middleware("http")
    async def request_context(request: Request, call_next) -> Response:
        request_id = uuid4().hex
        clear_contextvars()
        bind_contextvars(request_id=request_id)
        try:
            response = await call_next(request)
            response.headers["X-Request-ID"] = request_id
            log.info("request_completed", status=response.status_code)
            return response
        finally:
            clear_contextvars()

    @application.exception_handler(HTTPException)
    async def problem(request: Request, error: HTTPException) -> JSONResponse:
        return JSONResponse(
            status_code=error.status_code,
            media_type="application/problem+json",
            headers=error.headers,
            content={
                "type": "about:blank", "title": HTTPStatus(error.status_code).phrase,
                "status": error.status_code, "detail": error.detail,
                "instance": request.url.path,
            },
        )

    @application.get("/stations/{station}")
    async def station_count(station: str, counts: Annotated[Counts, Depends(get_counts)]) -> Count:
        return await counts.require(station)

    @application.get("/events")
    async def events(counts: Annotated[Counts, Depends(get_counts)]) -> StreamingResponse:
        async def snapshots() -> AsyncIterator[str]:
            for _ in range(2):
                count = await counts.require("central")
                yield f"event: count\ndata: {count.model_dump_json()}\n\n"
                await asyncio.sleep(0.2)
        return StreamingResponse(snapshots(), media_type="text/event-stream")

    @application.websocket("/live")
    async def live(socket: WebSocket) -> None:
        await socket.accept()
        service = cast(Counts, socket.app.state.counts)
        await socket.send_json((await service.require("central")).model_dump())
        await socket.close()

    if settings.instrument:
        FastAPIInstrumentor.instrument_app(application)
    return application
```

### Read the lab as a sequence of ownership decisions

`uv sync` prepares a virtual environment with the packages required by the lab, including its dev group for tests and linting. Executing the factory constructs one application instance. `FastAPI(lifespan=lifespan)` tells the app which async context to enter and exit. The fixture repository deliberately has no external connection, but in an adapter with a client, lifespan would own its setup and cleanup. `get_counts` is the request dependency that retrieves the service from application state. `Depends(get_counts)` associates the parameter with that provider so the route itself only calls the operation.

The fixture's success and missing cases exercise two distinct contracts. For a successful read, FastAPI serializes the response model. When the service reports a missing record using `HTTPException`, the exception handler turns it into a problem response. This is a compact lab adapter. If the same service must also be called by workers or CLIs, use a domain exception there and translate it to HTTP at the route or exception-handler boundary. The generated request ID is placed in the response and added to the log context. The HTTP middleware logs the response status, while the time at which a stream actually finishes requires a separate event or span.

The websocket test establishes message delivery and route access from an in-process client.

### Evolve the design without hiding system behavior

Replace the fixture with a repository backed by a real transaction and keep the route tests. Add an integration test that verifies how the backing system handles two concurrent updates. Introduce a simulated upstream dependency with a bounded latency, inject it into the service, and verify that a fast request can still finish while a slow one waits. Record baseline p50 and p95 latency before and after the change. Check that the latency measurement includes the operation you care about rather than only time to send status headers.

For rolling deployments, arrange for readiness to stop new work before draining current requests. Bound every in-flight operation within the shutdown window. If a task must survive restart, return an accepted response with an identifier backed by durable work. Treat local background tasks as process-bound. A queue, worker, status store, and idempotency contract are useful when the requested operation can outlive its caller.

## 5. Common Pitfalls & Debugging Playbook

### 1. One slow endpoint delays unrelated requests

**Symptom:** Latency climbs for simple endpoints while a handler runs blocking work.

**Root Cause:** The handler monopolizes the event-loop thread.

**Diagnostic:** Compare overlapping requests to the slow and fast routes and inspect event-loop lag alongside spans.

**Fix:** Use an async client for I/O. Move blocking operations to an appropriate worker and CPU-bound jobs to a process or queue.

### 2. Outbound connections accumulate

**Symptom:** Connection setup dominates request time and file descriptor pressure rises.

**Root Cause:** New pools are created per request or a stream is never closed.

**Diagnostic:** Compare client construction counts to request counts and inspect socket states.

**Fix:** Own shared clients in lifespan, close streamed bodies reliably, and bound the pool and operation timeouts.

### 3. Settings depend on the launch directory

**Symptom:** A service starts from a shell but deployment reads different values.

**Root Cause:** A relative dotenv location is resolved from the current working directory.

**Diagnostic:** Check the process working directory and the presence of required variable names without printing secret values.

**Fix:** Make runtime configuration explicit and validate it during startup.

### 4. Error logs cannot be joined to a trace

**Symptom:** A 500 appears in a proxy log with no correlated application event.

**Root Cause:** Context was not bound at the request boundary, or an event was logged outside the propagated task context.

**Diagnostic:** Send a single request and compare response headers, JSON log fields, and trace attributes.

**Fix:** Bind and clear request context consistently, propagate trace context across service calls, and never place request IDs in metric labels.

### 5. A retry creates duplicate writes

**Symptom:** A timed-out request triggers two side effects.

**Root Cause:** The first write completed, but its response was lost and the operation was replayed.

**Diagnostic:** Compare business keys and trace spans for both attempts.

**Fix:** Enforce idempotency and a bounded retry budget, or require reconciliation before retrying an ambiguous write.

## 7. Mastery Checkpoint Questions

### Q1. An async route calls a synchronous HTTP client directly. Why do other requests stall?
- A. The middleware resets the pool for every request.
- B. The call occupies the event-loop thread without yielding.
- C. HTTP responses can only be read by worker processes.
- D. A context variable blocks the event loop by design.

<details>
<summary>Answer & Explanation</summary>

**Answer: B.** Async concurrency requires cooperative suspension. Use an async I/O client or isolate blocking work from the loop.

</details>

### Q2. Where should a shared HTTP client be opened and closed for each application worker?
- A. Inside every route.
- B. In a per-request exception handler.
- C. In the application lifespan.
- D. Inside a cached property without a cleanup path.

<details>
<summary>Answer & Explanation</summary>

**Answer: C.** Lifespan gives resources explicit ownership and allows requests to reuse the pool across the worker's lifetime.

</details>

### Q3. Why should a request ID not be used as a Prometheus metric label?
- A. Unique IDs create an unbounded number of time series.
- B. Request IDs must always be integers.
- C. Prometheus has no labels.
- D. Labels prevent histogram creation.

<details>
<summary>Answer & Explanation</summary>

**Answer: A.** Each distinct label combination creates a series. Use a route template for metrics and put correlation IDs in logs or spans.

</details>

### Q4. A write times out after being sent upstream. What makes a retry safe?
- A. Always increasing the timeout.
- B. Retrying only over a new connection.
- C. Adding a larger delay.
- D. An idempotency guarantee or reliable confirmation that the first write did not commit.

<details>
<summary>Answer & Explanation</summary>

**Answer: D.** A lost response does not prove a failed write. Use a stable operation key or reconcile the outcome before replaying it.

</details>

### Q5. What should a timezone-sensitive service persist for an event that already occurred?
- A. An unzoned local wall-clock string.
- B. A timezone-aware UTC instant.
- C. The current UTC offset alone.
- D. A locale-specific display date without a time.

<details>
<summary>Answer & Explanation</summary>

**Answer: B.** Persist an unambiguous instant and apply a named timezone at display time so daylight-saving transitions are handled by appropriate rules.

</details>

### Q6. Design the lifecycle of a shared async upstream client in a FastAPI service. How would you verify that startup, request reuse, and shutdown all work while testing with different settings?

<details>
<summary>Answer & Explanation</summary>

Create one bounded client per worker in the lifespan context and expose it through a dependency. Close it when that context exits. In tests, scope settings overrides with monkeypatch and enter the TestClient context. Inject or instrument a fake transport to confirm multiple requests reuse the client and that it is closed during teardown.

</details>

### Q7. Several hundred tasks wait for the same client pool and requests start failing with pool timeouts. Which first change addresses the source safely?

- A. Add long retries around every pool timeout.
- B. Let each request create a new pool to avoid waiting.
- C. Wait indefinitely for a connection so callers never see a timeout.
- D. Bound accepted concurrency against the downstream capacity and measure pool wait time.

<details>
<summary>Answer & Explanation</summary>

**Answer: D.** Pool timeouts can reflect local saturation. Measure queue time and compare per-worker connection limits to total capacity. Bound queued work and preserve an overall request deadline. Immediate retries and independent pools increase contention.

</details>

### Q8. An SSE request receives HTTP 200, emits one event, then loses its upstream. How would you communicate the failure and let a client reconnect safely?

<details>
<summary>Answer & Explanation</summary>

HTTP status is already committed. Close the stream or send a documented in-band error event that contains no private details. Record the failure separately from the successful header send. If replay is part of the contract, assign each durable event a monotonic ID, accept a last-seen cursor at reconnect, define a bounded replay window, and handle a cursor older than retention explicitly.

</details>

### Review the choices you make when shipping an endpoint

| Question | What a design should specify |
| --- | --- |
| Where does input become trustworthy? | An explicit validation boundary, a separate output shape, and a policy for coercion and missing values. |
