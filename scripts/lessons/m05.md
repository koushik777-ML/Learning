## 1. The Mental Model

MongoDB groups related facts into a document. Start with what an operation reads and changes together, then ask how long that grouping remains bounded. Because a single-document change is atomic, the document boundary shapes correctness as well as performance.

Think of a repair shop. One intake sheet can hold the machine category and a few fixed observations. Its lifetime service history deserves separately numbered pages. Stapling every new result onto the original sheet makes every inspection and change steadily more expensive.

### Embed small value groups and reference independent histories

Suppose an assistant conversation has an owner, region, state, last-activity date, and a bounded preview. Those fields are needed together on the conversation list. Store actual messages separately if a conversation can grow indefinitely, and store tool attempts as their own records if they have a distinct retention policy or are queried across conversations. Use a stable event envelope with tenant and conversation scope, run ID, step, attempt number, outcome, and time. Large outputs need a bounded summary and an access-controlled pointer rather than unrestricted copies in every document.

| Model | Good fit | Cost |
| --- | --- | --- |
| Embedded child | Small, bounded group reads and changes with its parent | More writes can contend on the same document |
| Referenced child | Open-ended history, retention per event, or separate search | Reading the entire aggregate requires more queries or a join |
| Limited denormalized projection | A small preview speeds up a critical read | Refresh and reconciliation need an owner |
| Dedicated reporting projection | Reporting and write workloads have different shapes | Track reporting lag and replay strategy |

The BSON document limit is 16 MiB. Read payloads and contention often matter well before the limit. An ever-growing message array widens updates, increases index entries, and forces contention at the conversation root. A small embedded preview can still work if capped and clearly labeled as derived data.

A document store supports flexible shapes and can keep related values near one another. A relational store has useful structural tools for join-heavy models and invariants across several entities. MongoDB also supports joins through aggregation and multi-document transactions. If basic workflows need several joins and cross-record changes, compare both models experimentally. The presence of JSON-shaped input does not decide the database.

### BSON types, validation, and evolution

BSON preserves database types beyond JSON. An ObjectId is compact and includes a time component, but its order is insufficient for exact global event chronology. Timestamp and stable tie-breaker keys serve that purpose. BSON dates are UTC instants with millisecond precision. Accept timezone-aware datetime values and normalize on encoding and display. A string formatted like a date or ObjectId still compares as a string. For exact monetary amounts use minor units as integers or a deliberate Decimal128 policy. Approximate model scores have different requirements.

Choose a meaning for absent fields, null fields, and empty arrays. A null filter can include missing values. Use explicit existence or type checks when your contract distinguishes those states. Use a controlled interchange format or MongoDB Extended JSON when passing typed values between tools. A display-friendly conversion can discard the type needed on round-trip.

Give stored envelopes a schema version and core required fields. Validate semantic and presentation rules in Python. Use storage validators and indexes for rules shared by all writers, including scripts and services outside the typed application. For a field migration, permit compatible old and new shapes, update writers, migrate bounded batches, then tighten validation after observing the legacy shape disappear. This supports mixed application versions during rollout.

### Client lifetime, replication, and consistency

A client manages server discovery and pools. Share it in one application event loop and close it on shutdown. Server selection, pool checkout, execution, and network reads contribute different delays. Measure them independently. Cursor creation may defer work until iteration. A cursor obtains batches, so bound the result count, project only relevant fields, and close early if a large search is cancelled.

Replica-set writes reach the primary and are copied through a replication log. **Write concern** defines required acknowledgments. Majority acknowledgment under ordinary durable configuration reduces rollback risk on failover. **Read concern** controls which committed or local state a read can observe. **Read preference** chooses which replica-set member can serve a read. A reporting view can accept lag explicitly. A transition UI that must read its own acknowledged write across members can use a causally consistent session with the appropriate read and write concerns.

A single-document update is atomic. Put the expected current state in the filter and inspect matched or returned data. Two workers can have both read a pending run earlier, yet one conditional update wins. Use expiry and an ownership token for work that can be abandoned. A worker completing after a lease has been claimed again must fail the ownership check. External APIs need their own idempotency or fencing contract for this to protect effects outside the database.

Multi-document transactions help when a true invariant spans records. They require supported topology such as a replica set. Keep them short and handle transient outcomes according to driver guidance. Retried transaction callbacks should keep non-idempotent external effects outside the database decision. For high-throughput recording, stable event identities and scoped unique indexes can provide replay-safe updates without coordinating all events.

### Translate access paths into indexes

A **compound index** orders records by field sequence. A timeline filtered by tenant and conversation, then sorted by timestamp and ID, can use an index with those two equality keys followed by both sort keys. Continuation cursors need both sort values, scope, and matching direction. The initial prefix restricts the search, so this index will often be a poor fit for a timestamp-only query across all tenants.

Array fields create **multikey** entries. When two predicates must match the same array element, use an element-scoped query. Separate predicates can match separate elements. Each array can expand the number of indexed keys, and MongoDB restricts compound multikey indexes with multiple indexed arrays in a single document. Keep arrays bounded for write and storage costs.

A **partial index** contains documents that match its filter. The requested query must imply that filter for the index to return complete data. A partial unique index enforces uniqueness only among participating documents. A **TTL index** is a single-field date index managed by a background monitor. A zero interval treats the BSON date as the eligibility deadline for deletion. Cleanup is asynchronous. Your authorization or session lookup must enforce the timestamp itself, and deletion backlog still consumes resources.

### Break a report into dataflow steps

An aggregation pipeline transforms one stream of documents into another. An early match scopes the dataset and can use an index. Projection keeps or computes fields. Unwind multiplies rows by array length. Group folds rows by a key and may hold substantial intermediate state. Sort can require memory or spill when index order does not cover it. Limit is useful when it preserves the semantics. A lookup enriches from another collection, and the join values must have compatible types and available access paths.

For an hourly error report, match tenant and a half-open time interval first. Group by run and hour, increment attempts for every record and failures only for the target outcome. Sort by hour and run for deterministic pages. Measure input and output cardinality at each stage with representative data. A small index-supported lookup suits a request. A large report may need an asynchronous job or a maintained projection.

## 3. Complete Command, Query & Python Syntax Reference

### Connect once, bind typed values, and bound reads

```python
from datetime import datetime, timezone

from bson import ObjectId
from pymongo import AsyncMongoClient, DESCENDING

async def recent_turns(
    client: AsyncMongoClient, tenant: str, conversation: str, active_after: datetime,
) -> list[dict]:
    query = {
        "tenant": tenant,
        "conversation_id": ObjectId(conversation),
        "created_at": {"$gte": active_after.astimezone(timezone.utc)},
    }
    cursor = (
        client.workspace.turns.find(query, {"role": 1, "preview": 1, "created_at": 1})
        .sort([("created_at", DESCENDING), ("_id", DESCENDING)])
        .limit(20)
    )
    return [row async for row in cursor]
```

Construct the async client once and await its admin ping to verify reachability. The query scopes a typed conversation ID to its tenant and applies an inclusive lower time bound. Require a timezone-aware input. The projection includes three selected fields and the default document ID. The sort gives a strict order even when timestamps tie. The limit caps the result, and async iteration fetches batches. An empty conversation returns an empty list. Use a compound index on tenant, conversation ID, creation time descending, and ID descending for this path.

Await insert one to obtain an inserted ID, find one for a record or **None**, update one for matched and modified counts, and delete one for a deletion count. Modified count can be zero when a row matched but already had the new value. A multi-record write or delete can be appropriate for maintenance, with batches and a measured replication load.

### Atomically claim a pending record

```python
from pymongo import ReturnDocument

async def claim_run(collection, tenant: str, run_id: str, lease: str) -> dict | None:
    return await collection.find_one_and_update(
        {"tenant": tenant, "run_id": run_id, "state": "pending"},
        {"$set": {"state": "running", "lease_token": lease}, "$inc": {"fence": 1}},
        return_document=ReturnDocument.AFTER,
    )
```

The query combines scope, identity, and a state precondition. The set operation updates the state and owner, and the increment advances a monotonic fence. Returning the document after the update provides the winner's new state without a separate read. A second attempt against the running record returns **None**. Add expiration and include the active ownership fence in completion and renewal filters. Protect run identity with a compound unique index.

### Use validation, unique indexes, and expiry

A collection validator can require a JSON Schema with a BSON object root and explicit required fields and types. Strict validation evaluates writes against the validator, and error enforcement rejects failures. A schema validates document shape. For an ordering rule across independent documents, choose a suitable database invariant, model, or transition boundary. Review existing documents before tightening validation.

```python
await events.create_index([("tenant", 1), ("run_id", 1), ("seq", 1)], unique=True)
await sessions.create_index("expires_at", expireAfterSeconds=0)
await cases.create_index(
```

The first index makes a sequence slot unique inside a tenant and run, and serves ascending scans over that prefix. The second uses a BSON date as the asynchronous deletion deadline. The third helps recent open-case lookup after matching the tenant and open state. Reapplying an identical index definition works as setup. Changed settings need a migration. Compare execution statistics for keys examined, documents examined, documents returned, sort stages, and selected index. Verify the observed gains warrant write and storage cost.

## 4. End-to-End Real-World Reference Example (Python-Centric)

### Greenhouse control decision traces

A greenhouse team wants to count failed tool attempts in each control cycle and trace the chosen outcomes. Since one cycle can have many attempts, store them as separate events. Each event has a stable sequence identity, a compact outcome, and small sanitized metadata. Store large output elsewhere under the same visibility policy.

```text
greenhouse-traces/
  trace_lab.py
```

With Docker running, start a disposable MongoDB 8.0 server. Run the readiness check until it prints 1.

```bash
docker run --rm --detach --name atlas-greenhouse-db \
  --publish 127.0.0.1:27017:27017 mongo:8.0
docker exec atlas-greenhouse-db mongosh --quiet --eval 'db.adminCommand({ping: 1}).ok'
```

The port is published only on the host loopback address. This disposable instance uses local synthetic data. The ping checks server readiness and quiet mode omits the shell banner. If port 27017 is occupied, use an available host port such as 27018 and set **MONGODB_URI** to match. Save the following as **trace_lab.py**.

```python
import asyncio
import os
from datetime import datetime, timedelta, timezone

from pymongo import AsyncMongoClient


async def main() -> None:
    async with AsyncMongoClient(
        os.getenv("MONGODB_URI", "mongodb://localhost:27017"),
        serverSelectionTimeoutMS=3000,
    ) as client:
        await client.admin.command("ping")
        events = client.greenhouse_lesson.events
        await events.create_index([("tenant", 1), ("run_id", 1), ("seq", 1)], unique=True)
        await events.create_index([("tenant", 1), ("observed_at", 1)])
        day = datetime(2025, 4, 3, tzinfo=timezone.utc)
        fixture = [
            ("north", "run-1", 1, "ok", {"actuator": "fan"}),
            ("north", "run-1", 2, "failed", {"category": "timeout"}),
            ("north", "run-2", 1, "ok", {"actuator": "shade"}),
            ("south", "run-1", 1, "failed", {"category": "unavailable"}),
        ]
        for tenant, run_id, seq, outcome, context in fixture:
            key = {"tenant": tenant, "run_id": run_id, "seq": seq}
            await events.update_one(
                key,
                {"$setOnInsert": {
                    "observed_at": day, "schema_version": 1,
                    "outcome": outcome, "context": context,
                }},
                upsert=True,
            )

        pipeline = [
            {"$match": {"tenant": "north", "observed_at": {
                "$gte": day, "$lt": day + timedelta(days=1),
            }}},
            {"$group": {
                "_id": "$run_id",
                "attempts": {"$sum": 1},
                "failures": {"$sum": {"$cond": [{"$eq": ["$outcome", "failed"]}, 1, 0]}},
            }},
            {"$sort": {"failures": -1, "_id": 1}},
        ]
        async for row in await events.aggregate(pipeline):
            print(row["_id"], row["attempts"], row["failures"])


if __name__ == "__main__":
    asyncio.run(main())
```

Install the async driver with **python -m pip install "pymongo>=4.13,<5"**, selecting a 4.x release with the async API. Set **MONGODB_URI** if your local instance uses a different address. Run **python trace_lab.py**. You should see **run-1 2 1** followed by **run-2 1 0**. Run it again and confirm the counts stay fixed. After the lab, **docker stop atlas-greenhouse-db** removes the container and its disposable data.

The timeout bounds server selection and ping verifies connectivity. The unique compound index defines event identity. The query filter publishes that identity to the upsert, while set-on-insert initializes the rest once. The reporting index helps scope the tenant and time. The first pipeline stage matches a half-open window. The group increments total attempts and increments failures only when the outcome matches. The final sort orders failures decreasing and uses run ID to break ties. An awaited aggregate returns a cursor that the loop consumes in batches.

Now change the reporting tenant to south and predict one attempt and one failure for run-1. If a second writer supplies different data under the same identity, this lab keeps the original event. Production can compare stable payload fingerprints and report a conflict. When independent upserts race, handle duplicate keys and verify the existing record represents the same event. Apply retention and redaction independently. Restrict queries to the authenticated tenant, keep a bounded event projection, and avoid exposing unique identifiers or raw tool outputs in metric labels.

## 5. Common Pitfalls & Debugging Playbook

### 1. Long conversations slow down writes

**Symptom:** Writes retry more often and responses grow with conversation age.

**Root Cause:** One array contains all messages and tool results. It expands network and index work and creates a hot document.

**Diagnostic:** Inspect representative BSON sizes and compare examined keys and write latency by conversation length.

**Fix:** Move history to a child collection with scoped, ordered keys. Keep a strictly bounded preview and document its refresh process.

### 2. A reader accepts an already expired session

**Symptom:** A session is usable after its deadline.

**Root Cause:** TTL cleanup is asynchronous. A wrongly typed field also cannot serve as the intended expiry date.

**Diagnostic:** Inspect the BSON date and compare it to the authorization predicate and the index's expiration interval.

**Fix:** Query a typed deadline strictly later than the current instant. Keep background deletion as storage maintenance and pace large cleanup changes.

### 3. The query uses an index but scans many records

**Symptom:** The plan reports an index scan and latency still rises with collection size.

**Root Cause:** The chosen prefix may fit only part of the filter. A sort or selective partial predicate may be missing from the access path.

**Diagnostic:** Compare returned rows, examined documents, examined keys, sort stages, and the selected index in execution stats for several tenant sizes.

**Fix:** Align equality fields and sort keys, include a compatible partial filter where appropriate, and remeasure read and write costs.

### 4. A valid-looking ID or date returns zero matches

**Symptom:** The app passes the expected visible characters but finds no row.

**Root Cause:** The bound value and stored value have different BSON types.

**Diagnostic:** Inspect the stored field type and the driver's bound argument in a synthetic record.

**Fix:** Parse values at the application boundary and use schema validation. Migrate existing values deliberately and test old and new records.

### 5. A retried worker records a duplicate or overwrites a later outcome

**Symptom:** A timeout produces a repeated event or a stale worker replaces a newer result.

**Root Cause:** The event lacks a stable identity or a state transition omits the ownership fence.

**Diagnostic:** Compare tenant, operation ID, lease token, and payload fingerprint. Confirm whether the previous attempt reached the primary before its response was lost.

**Fix:** Protect a stable key with a unique index, use conditional transitions, and verify the active lease on completion. Use idempotency or reconciliation for effects outside MongoDB.
