## 1. The Mental Model

A Linux service is a process running under a particular identity, with a working directory, an environment, and open file descriptors. Diagnosing a deployment means finding which boundary failed: path traversal, process startup, socket binding, or connectivity from the client. Changing permissions or restarting a process before identifying that boundary can erase the evidence.

Think of a service as a workshop. The filesystem provides rooms, permissions define who can enter, the process is the worker, and the listening socket is the front desk. A client can only reach the application if the front desk is open at the address it called.

| Boundary | Question to ask |
| --- | --- |
| Filesystem | Can the service user traverse every parent directory and read the resource? |
| Process | Which executable, user, environment, and working directory are in effect? |
| Socket | Which process is listening on which interface and port? |
| Network | Does the name resolve, and can packets reach that socket? |

### Start with the state the kernel actually sees

A deployment describes intended state, but Linux makes decisions from current state. A configuration file may specify a new port while the running process still holds its old listening socket. An operator may have added a group membership after the service was started, so the running process still lacks that group. A log may report a valid check before a dependency changed. Compare the static definition, the live process or socket, and a representative request before calling a service healthy.

Keep the layers distinct. A service manager answers “is the program running under the expected conditions?” A listener answers “can a connection reach a process here?” A readiness request answers “can the process do the work I expect right now?” These can fail independently, so a restart is rarely the first useful experiment.

When investigating, capture the symptom and scope: who observes it, from where, since when, and whether it affects every request. Reproduce one bounded request from the expected path. Separate a falsifiable hypothesis such as “the service process lacks search permission on its config directory” from a broad description such as “permissions are broken.” Check the single condition and compare before and after your repair.

## 2. Core Architecture & How It Works Under the Hood

```text
 shell / systemd
       |
       | execve(program, arguments, environment)
       v
 +--------------------+        open()       +----------------------+
 | process (UID, PID) | -----------------> | /srv, /etc, /var/log |
 | current directory  |     mode + ACL      | directories / files  |
 +----------+---------+                     +----------------------+
            | bind() / listen()
            v
 +--------------------+     TCP connection     +------------------+
 | 127.0.0.1:8471     | <--------------------  | curl / HTTP client |
 | kernel socket     |                         +------------------+
 +--------------------+
```

1. A shell or service manager launches a program. The child receives the configured environment and working directory and runs with an effective user and group. A relative path starts at that working directory.
2. The kernel checks execute (search) permission on every parent directory, then checks access to the file. An ACL mask can restrict the effective permissions of a named ACL entry.
3. The process binds a kernel socket. A loopback bind accepts local traffic only. A wider bind still depends on routing and firewall rules.
4. A client resolves a hostname, connects, then sends HTTP. DNS, TCP, and HTTP failures require different diagnostics.
5. On shutdown, send a termination request and allow the program to finish in-flight work. A forced kill gives the process no chance to flush or clean up.

### Filesystem objects, names, and mount boundaries

The root directory `/` anchors one visible tree. Mounting a filesystem attaches another tree at a path. The running process may see a different tree from your shell if its mount namespace differs, which is common inside a container or a sandboxed service. A mount can hide files that existed at its mount point before the filesystem was attached. An apparent empty directory after startup can therefore reflect a mount decision independently of the backing files.

| Path | Typical purpose | Operational consequence |
| --- | --- | --- |
| `/etc` | Host and service configuration | Treat as controlled input. Keep writable application state elsewhere. |
| `/usr` | Installed programs and read-mostly system resources | Use the package manager to change installed software. Modern distributions often make `/bin` a symlink into `/usr/bin`. |
| `/var/lib/<app>` | Durable service data | Provision and back up the state directory as part of deployment. |
| `/var/log` | Persistent filesystem logs where applicable | Rotate and retain according to policy. Journald may use its own storage. |
| `/run` | Runtime state including sockets and PID files | Files may disappear at reboot. Recreate runtime directories during service startup. |
| `/tmp` | Temporary files and workspaces | Treat contents as transient. Use an API that creates a unique file or directory. |
| `/proc` and `/sys` | Kernel views of processes and devices | These expose live kernel state. Their entries are often generated on read. |

A directory entry maps a name to an inode. An inode represents the object and its metadata. A hard link is another name for the same inode and usually cannot cross filesystem boundaries. A symbolic link contains a path that must be resolved and can point across mounts. A process that already has a file descriptor references the open object even when another process renames or removes the pathname. For example, deleting a logfile removes a directory entry, but a logger with that file open can continue writing and consuming space until it closes the descriptor. Log rotation procedures should make the logger reopen the path.

Directory mode bits describe different operations from regular file mode bits. On a directory, read permits listing names and execute permits searching for a known name. Write plus execute permits creating or removing entries, subject to rules such as the sticky bit in shared temporary directories. Someone with write access to the containing directory may be able to replace a read-only file, so protect the directory as well as the file. For many shared handoffs, grant group search on the directory and group read on the file, with modification reserved for the producer.

### Processes, signals, and waiting

A running process has a PID, virtual address space, credentials, and a file descriptor table. A shell typically starts a child process with a fork-like operation and replaces the child program with an exec operation. The exec call keeps the PID and preserves file descriptors unless marked close-on-exec. A parent receives the child's wait status when it reaps the child. Until then, a terminated child can appear as a zombie. A zombie records exit information and has no application code left to run. Investigate the parent’s wait behavior when zombies accumulate.

In `ps` output, `R` includes runnable processes waiting for CPU, `S` is interruptible sleep, `D` is an uninterruptible kernel wait often associated with I/O, and `Z` is a zombie. A sleeping service can be healthy while waiting for connections. Compare CPU and time across several samples instead of assuming a single status letter explains the incident. A service blocked in `D` can retain a pending termination signal until it returns to an interruptible point. Inspect the dependency or device rather than sending repeated forced kills.

Use `SIGTERM` for orderly service stops. A cooperating program stops taking new work, waits within a defined budget, flushes state, and exits. `SIGINT` commonly arrives from Ctrl+C in the foreground terminal group. `SIGHUP` may cause a reload if the program defines that behavior. `SIGKILL` is immediate when the process can be scheduled for termination and cannot run cleanup handlers. Service managers can send an initial termination signal and escalate after `TimeoutStopSec`. Align that timeout with the application's own drain budget.

### DNS, sockets, and edge policy

For a named HTTP service, name resolution picks candidate addresses. The client then opens a socket, chooses a route, and tries a TCP connection. The kernel dispatches the connection to an appropriate listening socket. TLS, when present, validates the server identity and establishes an encrypted channel. HTTP runs after those steps. A timeout for a name lookup, a timeout in connection establishment, a TLS verification error, and a slow HTTP handler are different failures. A successful HTTP response proves the earlier layers worked sufficiently for that specific request.

The wildcard IPv4 address `0.0.0.0` covers local IPv4 interfaces. IPv6 `::` behavior for IPv4-mapped addresses depends on the socket and host settings. `127.0.0.1` and `::1` are loopback. An inbound firewall can allow traffic to a destination port from a specific subnet. Connection tracking lets stateful rules recognize replies and established flows. A service bound to the right address still depends on the host route, ingress policy, and surrounding infrastructure policy. Restrict service exposure to the expected interface and clients. Observe the applicable policy before changing it and verify from the expected origin afterward.

### What systemd does for a service

A unit file describes process launch, dependencies, and lifecycle. `After=` orders startup relative to another unit when both participate. `Wants=` requests startup of a dependency without imposing the stronger failure relationship of `Requires=`. Dependence and ordering are separate, and neither establishes application readiness on its own. A long-running process can report readiness explicitly with `Type=notify` when it supports the protocol. A typical Python process without notification support can use the default service type alongside health checks. Keep programs in the foreground so the manager can observe the correct process.

A service can direct output to the journal, restart after unexpected failure, and enforce runtime constraints. Persistent write directories and the service account belong in the deployment contract. If application code accepts untrusted input, reduce filesystem access to the paths it needs and inspect unit hardening independently of application correctness.

## 3. Complete Command, Query & Python Syntax Reference (Progressive)

### Files and service identity

```bash
pwd
id
namei -l /srv/health/config.json
chmod 640 config.json
chown appuser:appgroup config.json
setfacl -m u:auditor:r-- config.json
getfacl config.json
```

- `pwd` prints the current directory. `id` prints the user, primary group, and supplementary groups. Use them in the same context as the failing service.
- `namei -l` walks a path and lists ownership and permissions along the way. A readable file is inaccessible if a parent directory denies traversal.
- `chmod 640` grants owner read/write, group read, and no access to others. The digits are sums of read (4), write (2), and execute (1).
- `chown user:group` sets the owning user and group. It requires appropriate privilege, and changing owners can affect a running deployment.
- `setfacl -m` modifies an ACL. `u:auditor:r--` grants that named user read permission subject to the ACL mask. `getfacl` shows the effective rights. Use existing principals and directory policies.

### Processes and connectivity

```bash
ps -eo pid,user,stat,args
htop
ss -ltnp
curl --fail --silent --show-error --max-time 3 http://127.0.0.1:8471/health
dig +short example.com A
kill -TERM "$verified_pid"
```

- `ps -e` selects all processes. `-o` chooses columns (ID, owner, state, command). `htop` adds a live view of resource usage when installed.
- `ss -ltnp` lists listening (`-l`) TCP (`-t`) sockets, numeric addresses (`-n`), and available process info (`-p`). Inspect the local address as well as the port.
- `curl` fails on HTTP error responses with `--fail`, hides the meter with `--silent`, retains errors with `--show-error`, and caps total time with `--max-time`.
- `dig +short name A` queries for IPv4 records with compact output. Check AAAA separately for IPv6. DNS success alone does not establish that a TCP connection is allowed by a firewall.
- `kill -TERM` requests graceful shutdown of a PID you own or administer. Set `verified_pid` to the positive numeric PID you just verified. Check the command and owner before signaling.

### Service management and SSH

```bash
systemctl --user status health-lab.service
journalctl --user -u health-lab.service -n 20 --no-pager
sshd -t
```

`systemctl --user` talks to the current user's manager. `journalctl -u` selects the unit, `-n 20` limits entries, and `--no-pager` prints directly. Use `sshd -t` with appropriate read permissions to validate SSH server config and host keys before a reload. Verify a second key-authenticated login before changing authentication policy and keep the existing administrator session open. Limit allowed SSH principals and protect private keys with strict permissions and a passphrase.

### Reproduce a path permission decision with disposable files

```bash
umask 027
workdir=$(mktemp -d)
mkdir -- "$workdir/inbox"
printf '%s\n' 'ready' > "$workdir/inbox/job.txt"
stat -c '%a %U %G %n' "$workdir/inbox/job.txt"
namei -l "$workdir/inbox/job.txt"
```

`umask 027` masks group write and all other-user bits on newly created paths in this shell. An ordinary file creation requesting `0666` yields `0640`. A directory creation requesting `0777` yields `0750`. The mask does not change existing entries and can be superseded by default ACL inheritance. `mktemp -d` creates and prints a private temporary directory, often with mode `0700`. `--` ends option parsing. `printf '%s\n'` writes each string with a newline, and `>` creates or truncates the target. `stat -c` selects the output format. `%a` is mode in octal, `%U` and `%G` resolve user and group names, and `%n` prints the path. Expect mode `640` on the file on a typical local filesystem. Even if you share its group read bit, other users cannot traverse the private temporary directory.

Symbolic modes are useful for edits that should preserve unrelated bits. `chmod g+r config.json` adds group read. `chmod o-rwx config.json` removes other-user access. On a shared directory, a set-group-ID bit can make new entries inherit the directory’s group, which avoids per-writer group surprises. Access ACL entries grant rights on an existing object. Default ACL entries on a directory shape the access ACL of its children. Check the `effective` annotation from `getfacl` after an ACL change because the mask bounds the named-user and participating group entries.

### Narrow a service failure with read-only probes

```bash
getent ahosts localhost
ss -ltnp
curl --connect-timeout 1 --max-time 3 --silent --show-error \
  --output /dev/null --write-out 'status=%{http_code} connect=%{time_connect}s total=%{time_total}s\n' \
  http://127.0.0.1:8471/health
```

`getent ahosts` asks the configured system resolver stack and shows address and socket-type entries. This can reflect `/etc/hosts` and system name service configuration. `dig` queries DNS and can disagree when the application uses a local override or search suffix. Numeric addresses in `ss` avoid reverse-lookups obscuring the result. The long `curl` example separates a one-second connection limit from a three-second total budget. `--output /dev/null` discards the response body and `--write-out` prints status, time to connect, and total duration. A successful lab request reports `status=200`. A refused connection normally reports `status=000` along with an error. The measurement example intentionally reports HTTP error statuses. Automation that requires 2xx should additionally check the exact status, or use `--fail` if 4xx and 5xx are the relevant failures.

For repeated incidents involving a service, retrieve the narrow state you need with `systemctl show -p MainPID -p ActiveState -p SubState health-lab.service` under the appropriate user or system manager. `show` prints properties and repeated `-p` flags select fields. On a systemd-managed host, examine restart loops using the journal for that unit and boot. A failed unit does not by itself establish whether launch, configuration load, or a later exit failed. Track the first error before follow-on failures fill the journal.

### SSH identity and approved access

Two separate keys matter. The server host key identifies the host and is compared with a trusted fingerprint in the client’s known-host configuration. A user key demonstrates possession of a private key associated with a public key installed in the server account’s authorized-key policy. Keep the private key off the server and use a protected key store or agent with an appropriate lifetime. Review source-restricted access rules and allowed account groups with the administrators responsible for the host. Validate intended sessions before tightening authentication and retain a known-good administrative access path throughout the change.

Agent forwarding exposes the client's signing agent to processes that can access the forwarded socket while the session exists. Prefer an approved jump-host path that keeps private-key operations local. A host-key change might be an expected rotation or a routing mistake. Verify the new fingerprint through a trusted channel before updating the known host entry.

### Write automation with explicit status and cleanup

```bash
#!/usr/bin/env bash
set -eu
workspace=$(mktemp -d)
trap 'rm -rf -- "$workspace"' EXIT
target="${1:-http://127.0.0.1:8471/health}"
if curl --fail --silent --show-error --max-time 3 "$target" > "$workspace/result"; then
  cat "$workspace/result"
else
  printf '%s\n' 'Readiness probe failed' >&2
  exit 1
fi
```

The shebang selects Bash when executing the file directly. `set -e` exits after many unhandled failures but does not replace explicit control flow around conditionals, and `-u` catches unexpected unset variables. The parameter expansion uses argument one when nonempty, otherwise it uses the loopback default. Always quote paths and arguments established from variables. `trap ... EXIT` runs the quoted cleanup at shell exit and confines recursive removal to the directory created by `mktemp`. `>&2` sends the diagnostic to stderr. The script reports success only when the probe succeeds. When combining commands in a pipeline, use `set -o pipefail` if failures in earlier programs must influence the pipeline status. Prefer bounded retries around operations that can safely be repeated.

## 4. End-to-End Real-World Reference Example (Python-Centric)

A community weather station needs a local readiness endpoint that exercises access to a configuration file. Keep the bind on loopback and run under your existing account for the lab.

```text
health-lab/
  app.py
  station.txt
  probe.sh
  health-lab.service
```

**`app.py`**

```python
from http.server import BaseHTTPRequestHandler, HTTPServer
from pathlib import Path

STATION_FILE = Path(__file__).with_name("station.txt")


class Handler(BaseHTTPRequestHandler):
    def do_GET(self) -> None:
        if self.path != "/health":
            self.send_error(404)
            return
        try:
            station = STATION_FILE.read_text(encoding="utf-8").strip()
        except OSError:
            self.send_error(503, "Station configuration unavailable")
            return
        if not station:
            self.send_error(503, "Station name is empty")
            return
        body = f"ready: {station}\n".encode()
        self.send_response(200)
        self.send_header("Content-Type", "text/plain; charset=utf-8")
        self.send_header("Content-Length", str(len(body)))
        self.end_headers()
        self.wfile.write(body)


if __name__ == "__main__":
    with HTTPServer(("127.0.0.1", 8471), Handler) as server:
        server.serve_forever()
```

Put `Harbor East` in **`station.txt`**. Run the probe with Bash. Quoting preserves a URL argument as a single word, and the default is used when the argument is missing or empty.

**`probe.sh`**

```bash
#!/usr/bin/env bash
set -eu
url="${1:-http://127.0.0.1:8471/health}"
curl --fail --silent --show-error --max-time 3 "$url"
```

From the lab directory, run `python3 app.py`. From a second terminal in that directory, run `bash probe.sh`. Expect `ready: Harbor East`. Rename `station.txt` temporarily to see the probe fail with HTTP 503, then restore it. Stop the foreground process with Ctrl+C.

**`health-lab.service`** (optional on machines with a systemd user session)

```ini
[Unit]
Description=Weather station readiness lab

[Service]
WorkingDirectory=%h/health-lab
ExecStart=/usr/bin/python3 %h/health-lab/app.py
Restart=on-failure
RestartSec=2s
NoNewPrivileges=true

[Install]
WantedBy=default.target
```

`%h` expands to the user's home directory. `WorkingDirectory` fixes relative path resolution and `ExecStart` specifies the exact program and argument. `Restart=on-failure` retries crashes with a two-second delay. `NoNewPrivileges` prevents privilege gains via execution. With the files under `~/health-lab`, copy the unit to `~/.config/systemd/user/`, run `systemctl --user daemon-reload` and `systemctl --user start health-lab.service`, then run the probe again. Inspect the journal and stop the lab with `systemctl --user stop health-lab.service`. This small HTTP server is a lab fixture. Use a supported production server for real traffic.

### Acceptance and diagnosis in the lab

| Experiment | Expected observation | Boundary exercised |
| --- | --- | --- |
| Request the correct path with the station file containing its name | HTTP 200 and one line containing the station name | Client, socket, handler, and readable dependency |
| Request `/unknown` while the server is running | HTTP 404 | Network path is working, but this route does not exist |
| Empty the disposable station file or move it temporarily | HTTP 503 while the server remains reachable | Readiness depends on input state as well as process health |
| Stop your lab process and retry on loopback | Connection failure rather than HTTP 503 | The listening socket is gone |

The code resolves `station.txt` beside `app.py` through `__file__`, so a change of working directory alone does not break this specific lookup. To understand how `WorkingDirectory` affects other services, inspect a relative shell path from two directories, then compare it to an absolute path. Keep the program anchored to a known location or make the configured path explicit. Capture the working directory, process identity, address, and result at each lab step so you can reason from observations.

For a production analogue, keep the readiness response cheap, return the same minimal information on repeated probes, and avoid echoing sensitive settings into response bodies or logs. Use liveness to detect a process that cannot recover on its own. A transient dependency failure should stop new traffic through readiness without necessarily causing a restart loop. During shutdown, signal the managed service, remove it from traffic, drain within a deadline, and verify that the socket disappears.

## 5. Common Pitfalls & Debugging Playbook

### 1. Readable config returns permission denied

**Symptom:** The file is readable according to its mode, yet the service receives EACCES.

**Root Cause:** A parent directory lacks search permission, or a named ACL entry is restricted by its mask.

**Diagnostic:** Run `namei -l /srv/app/config.json` and `getfacl /srv/app`. Compare the result with the service identity.

**Fix:** Grant only the required traversal and read access to the service group or named user.

### 2. Health check works on the host only

**Symptom:** A local probe works, but another approved client cannot connect.

**Root Cause:** The process may be bound exclusively to loopback, or the intended network path is filtered.

**Diagnostic:** Inspect the bind address with `ss -ltnp` and compare a local probe to the client result.

**Fix:** Bind to the required interface and configure the approved firewall path and access controls for that service.

### 3. Works in a shell, fails under systemd

**Symptom:** A unit fails with missing files or a different interpreter.

**Root Cause:** Service environment and working directory differ from an interactive shell.

**Diagnostic:** Inspect `systemctl --user cat health-lab.service` and `journalctl --user -u health-lab.service -n 20`.

**Fix:** Set an explicit working directory and executable, reload unit definitions, then restart and probe the service.

### 4. A restart loses recent log entries

**Symptom:** The last writes disappear whenever a process is stopped.

**Root Cause:** A forced kill bypasses cleanup or application writes were buffered.

**Diagnostic:** Compare the unit stop timeout with shutdown duration and inspect exit signals in the journal.

**Fix:** Implement graceful termination and flush important data. Reserve forced termination for processes that cannot stop within the agreed time.

### 5. Filesystem usage stays high after log rotation

**Symptom:** The old log name disappeared, but reported space usage stayed high and the service has continued to write.

**Root Cause:** An open descriptor still points to the old inode. Removing a link does not release the inode’s data while a process retains that descriptor. A separate mount can also mean the path you inspected is on a different filesystem from the full one.

**Diagnostic:** Compare `df -h /var/log`, which reports the filesystem containing the path in human-readable units, with the visible entries. Inspect the service’s descriptors with `lsof +L1` where available and permitted. The link-count filter focuses on open objects with no remaining link. Match the finding to the service's PID and device.

**Fix:** Use the logger's supported reopen procedure or a controlled restart if required. Confirm that the descriptor is closed and filesystem capacity recovers. Teach the rotation job to reopen the service log and set retention limits to reduce recurrence.

## 7. Mastery Checkpoint Questions

### Q1. A service reads a file with mode 640 in a directory with mode 700 owned by another user. The service is in the file's group. Why does the read fail?
- A. Group permissions require the file owner to be logged in.
- B. The service cannot traverse the parent directory.
- C. Read-only group access only works on symbolic links.
- D. The service must bind a network socket first.

<details>
<summary>Answer & Explanation</summary>

**Answer: B.** The kernel checks directory search permission while resolving the path. The file's group read permission is checked only after the kernel can reach it.

</details>

### Q2. A local probe works on port 8471 and the remote client gets an immediate connection refusal. What check most directly tests whether the process is listening only on loopback?
- A. Read the client's DNS cache.
- B. Check file ownership of the probe.
- C. Inspect the local address reported by the listening socket.
- D. Compare the system clocks on both hosts.

<details>
<summary>Answer & Explanation</summary>

**Answer: C.** A socket listed as 127.0.0.1:8471 accepts IPv4 loopback traffic only. Check the bind first before changing network policy.

</details>

### Q3. A unit consistently fails with a missing relative config path, yet launching its executable from the project directory works. Which setting addresses the difference?
- A. WorkingDirectory
- B. RestartSec
- C. WantedBy
- D. Type

<details>
<summary>Answer & Explanation</summary>

**Answer: A.** Relative paths resolve from the current working directory. Set the directory explicitly, or use absolute paths for service resources.

</details>

### Q4. A service needs to flush buffered work before exit. Which signal is the appropriate first request for a graceful stop?
- A. SIGKILL
- B. SIGSTOP
- C. SIGCHLD
- D. SIGTERM

<details>
<summary>Answer & Explanation</summary>

**Answer: D.** SIGTERM can be handled by the process so it can stop accepting work and flush. SIGKILL cannot be caught.

</details>

### Q5. A hostname resolves correctly, and curl connects but reports HTTP 503. What did the probe establish?
- A. The server's application is fully ready.
- B. Name resolution and the connection succeeded, but the HTTP peer reported unavailability.
- C. The local port must be unbound.
- D. A firewall rejected the connection before HTTP.

<details>
<summary>Answer & Explanation</summary>

**Answer: B.** Receiving an HTTP response proves an HTTP peer was reachable. Inspect service readiness, dependency state, and logs next.

</details>

### Q6. An operator must diagnose a service that starts locally but fails to read its configuration after moving to a systemd unit. Outline checks that distinguish identity, path traversal, and service environment.

<details>

Walk the path with `namei -l` and inspect ACLs on the first inaccessible component. Fix only the missing traversal/read permission or use an explicit configuration path, then rerun the probe.

</details>

### Q7. A proxy sends traffic as soon as a unit reports active, but the application is still loading its first configuration. What should gate incoming traffic?

- A. A check of the unit's active property alone.
- B. The presence of the executable on disk.
- C. A representative readiness check after required initialization.
- D. An unconditional dependency restart after every failed check.

<details>
<summary>Answer & Explanation</summary>

**Answer: C.** The service manager observes the process lifecycle. A readiness check verifies that the service has finished the initialization required for serving, allowing callers to delay routing without treating normal startup as a crash.

### Q8. A logfile disappears from the directory after rotation but still occupies disk space. Explain what remains and what would release it.

<details>
<summary>Answer & Explanation</summary>

The removed name was a link to an inode. A logger still has an open file descriptor to that inode, so the kernel cannot reclaim the data until the final reference closes. Identify the service descriptor, have the application reopen the active log using its supported procedure, and verify space recovered on the correct filesystem.

</details>

## 8. Curated Deep-Dive References & Official Documentation

### Review the shortest path from symptom to evidence

| Observation | Most useful first evidence |
| --- | --- |
| A path appears readable, but the service gets permission denied | Check the service’s current identity, every parent directory, and the effective ACL. |
| The process starts then exits | Inspect the first journal error, executable, working directory, and settings source. |
| A request fails to connect | Compare the resolved address and listening socket before checking routing and the expected firewall policy. |
| An HTTP peer replies with an error | Trace application routing, request validation, dependency status, and handler logs. |
| A process stays alive after its termination budget | Verify the actual PID and inspect kernel wait state and blocked dependencies. |

Use the same path and identity as the failing operation. A root shell, an interactive user's environment, and a loopback test each answer a different question from an unprivileged service accessing a dependency. Compare one boundary at a time until the failure is localized.


- [GNU Coreutils manual](https://www.gnu.org/software/coreutils/manual/html_node/File-permissions.html) — Read file mode bits and the distinction between directory search and ordinary file execution.
- [Linux manual: path resolution](https://man7.org/linux/man-pages/man7/path_resolution.7.html) — Follow path traversal from the starting directory through permission checks on each component.
- [systemd.service manual](https://www.freedesktop.org/software/systemd/man/latest/systemd.service.html) — Compare service types and read the restart policy table.
- [curl command-line manual](https://curl.se/docs/manpage.html) — Compare connection timeouts, maximum duration, and HTTP failure behavior.
- [OpenBSD sshd_config manual](https://man.openbsd.org/sshd_config) — Read the public-key authentication, allowed principals, and administrative login settings.
