## 1. The Mental Model

Retrieval-augmented generation (RAG) gives an answerer access to external evidence at request time. A model can write convincingly from patterns in its weights, even when a policy has changed or the user asks about a record it was never trained on. A retrieval system selects authorized source passages, and the answerer uses those passages under an explicit evidence and citation policy.

Imagine an archivist preparing a briefing. The archivist needs the right edition, the pages surrounding a clause, a way to cite them, and permission to show them. A page that mentions the search terms but lacks the operative sentence is insufficient evidence. The same applies to a plausible-looking vector match.

### Separate the capabilities before integrating them

| Capability | Example | Responsibility |
| --- | --- | --- |
| Exact transaction lookup | Has case X shipped? | Typed lookup against the system of record with authorization |
| Policy question | Is there an allowance for fragile inventory? | Retrieve effective passages, with sections and citations |
| Structured aggregation | How many cases closed last quarter? | Bounded database query against well-defined fields and time zones |
| Conversation state | What draft was I refining? | Load scoped recent turns and the current user-confirmed goal |
| Durable memory | I prefer evening study sessions | Store and retrieve a typed, revisable preference with provenance |
| Unsupported request | Which policy will be effective next year? | Clarify or abstain when reliable evidence is unavailable |

Context engineering is deciding what information enters the model, in what order, under which trust boundaries, and with which token budget. The longer the prompt, the more potential distractors it contains and the more expensive each request becomes. Treat the context as an assembled request from versioned inputs. It should expose enough detail for a supported answer and enough source metadata for reviewers to verify it.

**Retrieval quality and answer quality are different failure domains.** If the best passage never enters the candidate pool, an excellent answer model cannot recover it. If a good passage reaches context and the model ignores it or invents a number, start with evidence ordering, the prompt contract, and the answer model. Track both stages before buying a larger model.

### Work backward from an evidence requirement

Suppose a policy states that a local permit is valid for 30 days except under a separately named appeal extension. A suitable response identifies the ordinary duration and the extension's conditions with citations. Returning only the first sentence can be materially wrong even if an evaluator matches “30 days.” Your retrieval fixtures should therefore specify the set of evidence required, including metadata such as section and applicable date. Answer tests should score applicability, citation support, and abstention separately.

A model grades textual relevance imperfectly. Decide which properties can be checked deterministically before invoking one. A citation ID either exists in the context or it does not. A cited document either belongs to the correct tenant and effective interval or it does not. Whether a sentence entails a synthesized claim may still need human review or a calibrated grader.

## 2. Core Architecture & How It Works Under the Hood

```text
OFFLINE INGESTION
 authorized source -> parse/layout -> normalize -> semantic chunks + provenance
                                           |
                  +------------------------+----------------------+
                  v                                               v
       lexical inverted index                        embedding + vector index
                  |                                               |
ONLINE REQUEST    |                                               |
 authenticated request -> choose lookup / retrieval / clarification
                  |                                               |
                  +------ authorized lexical and dense search ----+
                                    |
                    fuse IDs -> rerank query + text pairs
                                    |
                deduplicate -> budget sections -> verify provenance
                                    |
                   grade evidence -> answer with citations
                       |                  |
           optional bounded rewrite      +--> unsupported -> abstain
```

### Ingestion, provenance, and indexing

Parse documents into a canonical structure before embedding them. Preserve heading hierarchy, document identifier, version, original URL or page location, line or character range, effective dates, and access scope. HTML often contains navigation and repeated footers. PDFs can yield out-of-order text, repeated headers, or hidden text artifacts. Scanned pages need OCR and quality checks. Tables are relationships between row labels, column labels, and cell values. A chunk containing only the numeric cells loses that relationship. Preserve a heading path and enough row/column labels to make the entry self-explanatory.

Chunk along meaningful boundaries first, such as a heading section, paragraph group, or contract clause. Split oversized sections within those boundaries based on the tokenizer for the chosen retrieval and generation models. Start with a few hundred tokens and modest overlap, then compare against an evidence-labeled dataset. Smaller chunks improve specific matching but can omit definitions or exceptions. Larger chunks preserve surrounding context but dilute retrieval. Parent-child retrieval provides searchable small spans that point to a larger contextual parent. When more than one span hits the parent, include that parent once.

Stable citation IDs should point to a particular immutable source revision and location. Idempotent ingestion writes a new retrieval snapshot, verifies fixture results, and atomically publishes the snapshot. A stable external source ID can have multiple revisions. A question about the current policy selects the currently effective revision, while a historical question explicitly selects its date. If rules are tenant-specific, apply tenant and access predicates during candidate retrieval. Filtering after a global top-k can starve authorized results and risks exposing unauthorized text at another stage.

### Complementary retrieval and fusion

**BM25** is a lexical ranking function built on term statistics. It typically rewards queries where rare terms match documents, reduces gains from repeated instances of the same term, and adjusts for document length. An inverted index maps terms to containing records and counts. It excels at exact identifiers, error messages, and product names. Analyzer choices matter. A stemming analyzer can help natural-language variations while changing identifiers. Preserve identifiers in a dedicated, exactly analyzed field.

**Dense retrieval** encodes query and document text into vectors with a matched embedding model. Similarity follows the model's learned notion of meaning. It can recover paraphrases or conversational questions with different vocabulary. It may still miss unfamiliar exact identifiers, numerical constraints, and distinctions not represented in model training. Approximate indexes trade recall for speed. Probe exact search on a sample to distinguish poor embeddings from insufficient index search effort.

Combine results using rank aggregation or a calibrated scoring scheme. Reciprocal rank fusion gives a record a contribution of 1 divided by a constant plus its rank for each retriever where it appears. The constant smooths rank differences. This is useful when lexical and dense scores are on incompatible scales. If A is first lexically and second densely, it receives contributions from both lists. If B appears once at rank one, it gets one term. Deduplicate candidate IDs and choose how many to pass forward with measured recall and latency.

A **cross-encoder** reads the query and candidate passage together and produces a learned relevance score. It can distinguish a claim from a nearby exception because token interactions see both inputs simultaneously. Running it over the whole corpus would be too expensive for normal request budgets. Rerank tens of candidates after efficient retrieval. Its scores describe relevance under its training distribution. They do not assert source authority, tenant access, or factual support.

### Routing, rewriting, and evidence grading

Route intent first. A typed order or inventory lookup gets data from a fixed backend with authorization, while a question about handling policy goes to retrieval. In ambiguous situations, preserve exact facts and ask for clarification instead of choosing a tool arbitrarily. A rewrite turns conversational references into a searchable query. For “Does that also apply to international orders?” preserve the original question and resolve “that” using conversation state. Run the original and the rewrite together when the new wording may erase an identifier.

Self-correction is a bounded state transition. Retrieve once, then grade whether the context has the applicable clause, necessary definitions, and exceptions. If weak because the query is vague or lexical matching failed, permit one targeted rewrite and retry. Validate any referenced sources and return a citation or an explicit evidence gap. Track why you retried and cap queries, elapsed time, and output length. A loop that keeps changing queries until some passage appears can turn uncertainty into false confidence.

### Context and caching

Construct the prompt in a stable order. Put unchanged instructions and schema first, then trusted request metadata, then clear labels around retrieved passages and the user's actual question. A decoder distinguishes instruction roles imperfectly when documents contain similar language. Delimiters and typing clarify the contract. Tool capabilities still need their own enforcement.

An inference **KV cache** stores attention intermediates for prior positions while generating a continuation. A **prompt/prefix cache** can reuse work across requests sharing an exact token prefix under a runtime or provider's contract. Stable prefixes improve hit rates. Appending tenant-specific or rapidly changing text near the beginning can fragment the cache. Distinguish token-prefix reuse from an application result cache. The latter returns a previous query or answer and requires explicit tenant, authorization, corpus revision, model/version, and expiry keys. Never serve cached private answers across tenants or after permission changes.

### Memory tiers and lifecycle

Conversation memory is application-managed state, even when the model appears to remember. Keep recent turns and unresolved actions in short-term state, often Redis with a TTL for quick retrieval. Store durable user-confirmed preferences or facts in a relational store if ownership, versions, and uniqueness matter. An append-only episode record in Postgres or MongoDB can retain interactions with schema or event evolution. Semantic memory uses embedding search over permitted memories and should keep text, embedding profile, and evidence source linked. Graph memory models relationships as typed edges with provenance, perhaps using node and edge tables in Postgres when queries are bounded. Add a graph-specific store only for query patterns that benefit.

Different memory types need different write policies. A private note may never leave its session. A preference update may require explicit approval. A fact inferred by a model stays provisional until verified. Add a stable subject and preference key, source, time, confidence where useful, retention, and supersession. Retrieve the latest active row by key before semantic comparison. Deleting a user should remove or revoke entries from primary records, vector indexes, caches, and queued derived work. Exercise these actions, including retries after partial cleanup.

## 3. Complete Command, Query & Python Syntax Reference (Progressive)

### Fuse candidates by rank

```python
def rrf(*rankings: list[str], k: int = 60) -> list[str]:
    scores: dict[str, float] = {}
    for ranking in rankings:
        for rank, identifier in enumerate(dict.fromkeys(ranking), start=1):
            scores[identifier] = scores.get(identifier, 0.0) + 1 / (k + rank)
    return sorted(scores, key=lambda identifier: (-scores[identifier], identifier))

print(rrf(["A", "B"], ["C", "A"]))  # ['A', 'C', 'B']
```

Each ordered list contributes rank positions starting at 1. `dict.fromkeys` keeps the first instance of duplicate IDs. `k` is a positive smoothing constant. Larger values narrow the relative difference between early and late positions. The key sorts by descending fusion score, then by ID for repeatable ties. Preserve individual rank, total candidates, and latency alongside the fused list for diagnosis.

### Pair relevance with a cross-encoder

```python
from sentence_transformers import CrossEncoder

query = "When is a wetland survey permit valid?"
candidates = ["Permits expire after 30 days.", "Field staff collect water samples."]
ranker = CrossEncoder("cross-encoder/ms-marco-MiniLM-L6-v2")
scores = ranker.predict([(query, passage) for passage in candidates], batch_size=8)
print(candidates[max(range(len(scores)), key=lambda i: scores[i])])
```

`predict` accepts query/passage pairs and returns one score per pair for this checkpoint. `batch_size` bounds how many pairs enter an inference batch in one call. Passages for real reranking carry stable source IDs so you can preserve provenance even when text repeats. The permit sentence should outrank the unrelated water statement. Answering the validity question may still require an issued date or another passage. Relevance and completeness are separate checks.

### Choose filters and versions before searching

A PostgreSQL full-text search can compute `ts_rank_cd(document_search, websearch_to_tsquery('english', question))` after a predicate that restricts tenant and document revision and tests whether the document matches the query. The first argument is the stored token vector, usually GIN-indexed for filtering. The second argument interprets familiar search syntax with the same language configuration as indexing. `ts_rank_cd` scores cover density, a lexical ranking signal. It is distinct from BM25, so keep engine and ranking version in evaluation records.

To avoid loading unneeded context, represent each candidate as an immutable record with a textual ID, corpus revision, location, token count, and access attributes. Allow only authorized IDs to enter fusion and reranking. Accumulate candidates in rank order while budgeting both source text and wrapper metadata. Reserve model context for the question, fixed prompt, and response. Use the actual tokenizer to count the final rendered prompt. A selected paragraph can fit when counted alone yet overflow after source headers, chat delimiters, and nearby necessary passages are added.

### An explicit request result

Use a result object with a decision such as answered, needs clarification, or insufficient evidence, plus citations for answered claims. A citation should reference a retrieved evidence ID instead of an arbitrary URL generated by the model. Reject IDs outside the context set. If a required source is missing or overdue, prefer a predictable fallback over a guess. Log request class, corpus/index and encoder versions, retrieved IDs and ranks where permitted, duration per stage, and outcome. Avoid logging raw user text and document bodies by default. Build dashboards for retrieval misses and unsupported citation rates separately.

## 4. End-to-End Real-World Reference Example (Python-Centric)

A community theater wants to return the right room-use evidence to an organizer. The fixture contains competing wording, a clause visible only to another theater, and an unsupported question. This offline lab uses exact terms and an explicit fixture that stands in for dense semantic rankings. It exercises retrieval contracts without external services. The live cross-encoder example in Section 3 shows how to score query/document pairs when moving beyond the fixture.

```text
theater-evidence/
  demo.py
```

```python
from dataclasses import dataclass
import re

@dataclass(frozen=True)
class Passage:
    id: str
    tenant: str
    body: str

CORPUS = (
    Passage("annex/1", "annex", "Lobby reservations close 10 days before a show."),
    Passage("annex/5", "annex", "Stage lighting must be reset after rehearsal."),
    Passage("metro/2", "metro", "Lobby reservations close 2 days before a show."),
)
DENSE_RANKS = {
    "how far ahead do we book the entrance hall": ["metro/2", "annex/1"],
    "when do tickets become refundable": [],
}
KEYWORDS = {"lobby", "reservation", "reservations", "lighting", "rehearsal"}

def tokens(value: str) -> set[str]:
    return set(re.findall(r"[a-z]+", value.lower()))

def retrieve(tenant: str, query: str) -> list[Passage]:
    allowed = {item.id: item for item in CORPUS if item.tenant == tenant}
    terms = tokens(query) & KEYWORDS
    exact = sorted(allowed, key=lambda key: (-len(tokens(allowed[key].body) & terms), key))
    lexical = [key for key in exact if tokens(allowed[key].body) & terms]
    dense = [key for key in DENSE_RANKS.get(query.lower(), []) if key in allowed]
    fused: dict[str, float] = {}
    for ranking in (lexical, dense):
        for rank, key in enumerate(ranking, 1):
            fused[key] = fused.get(key, 0.0) + 1 / (60 + rank)
    return [allowed[key] for key in sorted(fused, key=lambda key: (-fused[key], key))]

for question in ("how far ahead do we book the entrance hall",
                 "when do tickets become refundable"):
    hits = retrieve("annex", question)
    if hits:
        top = hits[0]
        print(f"[{top.id}] {top.body}")
    else:
        print("Insufficient evidence in this theater's collection.")
```

Run `python demo.py` with Python 3.12. The first output starts `[annex/1]` with 10 days, even though the semantic fixture ranked `metro/2` first. The second query abstains. `@dataclass(frozen=True)` creates value-like passage objects whose fields cannot be reassigned. `allowed` builds the authorized request scope. The lexical stage counts matching keywords as a transparent baseline. The semantic fixture returns sorted IDs, and the fusion logic consumes only IDs allowed in the authorized scope. In a built index, the retrievers should apply scope before selecting their top candidates. The demo uses an in-process check over fixtures to show the expected behavior at the fusion boundary.

Return the evidence verbatim as a dependable first interface. Add generation only after retrieval tests pass. In a larger service, update the toy keyword count to BM25 and the stub ranks to a real encoder and vector index. Write fixtures for exact clause labels, paraphrases, negation, and older versions. Verify a changed record cannot stay live after deactivation and that a nonmember receives a generic response without the tenant's document IDs.

For a realistic release gate, evaluate first-stage recall@k, ranking at the point where budget cuts candidates, citation correctness, answer quality, and abstention. A policy can be wrong if it omits an exception even if recall@1 is perfect on the main passage. Evaluate cases needing multiple passages and label the complete required evidence set.

## 5. Common Pitfalls & Debugging Playbook

### Exact identifiers disappear from otherwise good search

**Symptom:** Paraphrases work but known requests such as “policy A19-X” return similarly worded unrelated passages.

**Root Cause:** The encoder has limited discrimination between rare identifiers or the lexical analyzer split meaningful punctuation.

**Diagnostic:** Print lexical tokens and ranks for the exact identifier and a semantic variant. Check matching on an exact-key field and compare candidate union.

**Fix:** Keep a dedicated exact field, add lexical candidate retrieval, and fuse results. Evaluate both exact and paraphrase classes.

### Citations exist but do not support the answer

**Symptom:** Answer sentences point to true page IDs yet omit conditions or give numbers absent from evidence.

**Root Cause:** Relevance was treated as evidentiary support. Candidate budgeting may have trimmed definitions or exceptions.

**Diagnostic:** Audit every substantive claim against the exact spans in the final prompt. Compare the candidate pool with the selected context.

**Fix:** Preserve section/parent context where needed. Check applicability and support before returning a claim, and abstain on material gaps.

### Wrong scope or version shows up after ingestion

**Symptom:** A newer revision publishes successfully but requests still cite the old one or a different tenant.

**Root Cause:** A cache or index partition key lacks corpus version or authoritative permission scope. Derived indexes may lag revocation.

**Diagnostic:** Trace effective date, tenant ID, authorized index, candidate IDs, and cache key on a failing fixture.

**Fix:** Scope retrieval and result caches by effective access and version. Atomically publish verified indexes and remove revoked data from derived stores.

### A rewrite makes evidence worse

**Symptom:** The first query finds a relevant policy, but the rewritten query retrieves only a broader topic.

**Root Cause:** The rewrite dropped constraints or an exact name. The gate evaluated topic familiarity instead of the required evidence.

**Diagnostic:** Compare original/rewrite terms and stage-level ranks for the deleted phrase. Measure which passages survived context packing.

**Fix:** Run original and rewritten queries together, keep key entities, and bound retry count. Preserve the strongest verifiable evidence or abstain.

### Memory keeps reintroducing a corrected preference

**Symptom:** After a correction, the application periodically returns to the old preference.

**Root Cause:** An embedding index or cached summary still contains a superseded record and retrieval does not filter its status.

**Diagnostic:** Follow the preference key from authoritative row through summary, vector index, and result cache. Compare provenance and ordering.

**Fix:** Mark supersession in the durable store, exclude old records during retrieval, and invalidate affected projections. Test the entire update and deletion trail.

## 8. Curated Deep-Dive References & Official Documentation

### Review offline

A trustworthy answer needs both applicable evidence and reasoning that stays inside it. Check the chain in order: parsing preserves headings and locations, chunking preserves enough context, candidate retrieval enforces scope, fusion and reranking surface evidence, prompt construction preserves definitions and exceptions, and the answer cites only what was supplied. If a test fails, identify the earliest broken link before tuning the last model.

Remember the difference between a document revision, an embedding profile, and a cache permission key. A document revision changes the evidence. An embedding profile changes the searchable coordinate system or preprocessing. The cache key determines when previous work can be reused safely. Changing one can require flushing or rebuilding affected projections without changing the others.
